# 教师综合发展平台｜效果图转 HTML 与业务闭环交付任务清单

> 工作分支：`delivery-html-business-prototype`  
> 文档用途：作为后续图片校验、页面清单、HTML 原型、业务逻辑说明和开发交付的执行清单。  
> 执行原则：先识别真实图片内容，再判断业务归属；先校验页面逻辑，再还原 HTML；每批提交后由人工审核。

---

## 一、总体目标

将仓库 `效果图/` 下的教师综合发展平台效果图整理为一套可交换、可审查、可交付开发的 HTML 原型与业务说明包。

最终交付不只是页面视觉还原，而是同时说明：

1. 页面真实内容是什么。
2. 页面属于哪个端、哪个模块、哪个业务流程。
3. 页面字段、按钮、状态是否符合业务逻辑。
4. 教师端动作如何被管理端承接。
5. 哪些页面进入开发交付，哪些页面需要合并、下沉或暂不进入。
6. 每个页面如何转为可浏览 HTML 原型。
7. 开发需要关注哪些字段、状态、权限和接口边界。

---

## 二、工作原则

### 2.1 不按文件名直接判断页面

当前仓库中的图片文件名可能与图片真实内容不一致。因此所有页面归属判断必须以图片内容为准，包括：

- 页面顶部标题
- 面包屑
- 左侧菜单选中项
- 底部 Tab 选中项
- 主卡片标题
- 表格字段
- 状态标签
- 按钮文案
- 页面业务对象
- 前后流程关系

### 2.2 先校验，再还原

执行顺序固定为：

```text
图片路径整理
→ 图片真实内容识别
→ 文件名与内容一致性校验
→ 页面归类与取舍
→ 页面地图草案
→ 业务闭环审计
→ HTML 原型还原
→ 页面说明补充
→ 开发交付整理
```

### 2.3 分批提交，人工审核

每一批完成后提交到工作分支，不直接合并主分支。用户审核后，再进入下一批。

## 五、审核点

每一阶段交付后，需要人工审核以下问题：

1. 页面真实内容识别是否准确。
2. 页面归属是否准确。
3. 是否存在文件名误导。
4. 是否存在重复页或历史版本页。
5. 字段是否有明确业务理由。
6. 按钮是否代表真实操作。
7. 状态是否能形成闭环。
8. 教师端文案是否足够口语化。
9. 管理端是否能承接教师端动作。
10. AI 是否只作为辅助能力，不越权形成正式结论。
