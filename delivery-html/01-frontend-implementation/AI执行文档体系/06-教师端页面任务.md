# 06｜教师端页面任务

> 本文件用于指导教师 PC 端和教师手机端页面还原。教师端必须使用更轻量、更温和、更口语化的表达，避免管理端术语直出。

## 1. 教师端总体原则

```txt
1. 教师端不是管理后台
2. 页面语气要轻量、低压、可理解
3. 教师端不得直接出现“候选数据”
4. 教学反思不使用“截止时间”“提交”等高压表达
5. 系统消息入口和待办入口不能混用
6. AI 只做辅助整理、建议和解释
7. 教师只需确认、完善、保存，不被迫理解后台规则
```

## 2. 教师端术语规则

教师端可用：

```txt
待确认记录
系统识别记录
待确认材料
待你确认
已入档
已保存
可完善
待补充
继续整理
完善一篇教学反思
```

教师端禁止或不建议：

```txt
候选数据
证据缺口
规则校验失败
提交教学反思
截止时间
影响年度报告
AI 已正式判定
AI 自动审核通过
```

## 3. 教师 PC 端布局

教师 PC 端顶部导航固定为：

```txt
首页｜成长档案｜能力画像｜发展活动｜个人报告
```

规则：

```txt
1. 消息铃铛进入系统消息
2. 查看全部待办进入全部待办页
3. AI 助理位于右下角
4. 页面风格轻量、温和、面向教师
```

## 4. 手机端布局

手机端设计宽度：

```txt
390px
```

底部 Tab 固定为：

```txt
待办｜档案｜AI 助理｜活动｜我的
```

规则：

```txt
1. AI 助理位于底部中间
2. 不出现手机外壳、浏览器壳、透视效果
3. 页面适合碎片化查看与轻量处理
4. 页面不堆复杂规则说明
```

## 5. 手机端首批页面

```txt
1. 教师端手机｜待办首页
2. 教师端手机｜全部待办
3. 教师端手机｜系统消息
4. 教师端手机｜档案首页
5. 教师端手机｜活动首页
6. 教师端手机｜我的首页
7. 教师端手机｜能力画像
8. 教师端手机｜个人发展报告
```

目标：跑通教师移动端核心使用路径。

## 6. 手机端待办规则

待办文案必须是一件具体可执行的事。

推荐示例：

```txt
确认一条培训证书
完善一篇教学反思
补充一份培训总结
继续整理教学反思
```

不推荐：

```txt
补齐聘期要求证明缺口
处理候选数据
完成发展任务
提交教学反思
```

## 7. 系统消息与待办边界

```txt
右上角铃铛 → 系统消息
查看全部待办 → 全部待办页面
底部待办 Tab → 待办页面
最近动态 / 全部动态 → 已完成、已保存、已记录的动态
```

不得把系统消息与待办混为同一页面。

## 8. 档案页面规则

手机端档案页应包含：

```txt
搜索 / 语音搜索
档案概览
八个维度入口
最近入档
记录详情
待确认记录流程
```

八个维度：

```txt
基本信息
教学工作
教研科研
企业实践
社会服务
成果荣誉
个人发展
考核评价
```

## 9. 活动页面规则

活动包括：

```txt
教学反思
培训进修
企业实践
虚拟教研
```

教学反思表达应使用：

```txt
完善一篇教学反思
继续整理教学反思
保存草稿
```

不使用：

```txt
提交反思
截止时间
必须完成计划
```

## 10. 我的页面规则

我的页面包括：

```txt
能力画像
画像用到的记录
目标岗位对照
聘期要求对照
个人发展报告
```

能力画像固定口径：

```txt
四轴雷达：教学、教研、实践、服务
基本能力在中心显示，不作为雷达轴
等级区间：新手、胜任、骨干、名师
画像不是评价结论，是发展支持解释
```

能力颜色固定：

```txt
教学 #4A90E2
教研 #F5A623
实践 #7ED321
服务 #BD10E0
```

```md
- [ ] 没有直接出现“候选数据”
- [ ] 没有管理端强管控语气
- [ ] 待办是一件具体可执行的事
- [ ] 教学反思没有“截止时间”
- [ ] 消息入口和待办入口不混用
- [ ] AI 只体现辅助作用
- [ ] 手机端 390px 宽度下可读
- [ ] 底部 Tab 正确
- [ ] 状态标签使用教师端文案
```
