# 第 0 步第二批补充｜教师端档案模块页面取舍决策

> 分支：`delivery-html-business-prototype`  
> 关联文件：`delivery-html/00-image-audit/teacher-mobile-archive-audit.md`  
> 目的：对档案模块校验表中的待确认项做产品决策，作为后续 HTML 原型与业务逻辑说明的执行依据。

## 1. 决策原则

本次不再等待逐项确认，按以下原则收敛页面：

1. **先闭环，后补全**：优先保留能跑通“正式档案查看 + 纠错更正”的页面。
2. **先概括，后记录**：维度页先展示该维度下的内容概括，再下钻到记录列表和详情。
3. **一类页面只保留一个最终版本**：有版本一、版本二、版本三时，只选择一个进入首批 HTML。
4. **教师端弱化管理化表达**：不把“管理、权限、配置、工作流、高级搜索”这类后台语义直接交给教师端。
5. **避免制造压力感**：发展计划、档案草稿等概念如无强业务闭环，先不进入首批。
6. **不因文件名排除图片**：疑似误命名图片进入后续视觉复核队列，不阻塞当前主闭环。

## 5. 后续执行要求

后续进入 HTML 阶段时，档案模块按以下要求执行：

1. 页面文案必须面向教师，不使用“候选数据”“绩效管理”“权限配置”等管理端词汇。
2. 档案模块默认展示正式档案，待确认记录仍由待办模块承接。
3. 纠错更正结果需要说明“已提交 / 待核验 / 已补充 / 已更正”的状态，不允许提交后直接变成正式更正完成。
4. 八维档案必须完整覆盖：基本信息、教学工作、教研科研、企业实践、社会服务、成果荣誉、个人发展、考核评价。
5. 维度页必须先呈现概括，再进入记录列表，不直接把列表作为维度首页。
6. 所有来源、入档时间、引用情况只在详情页或说明区出现，避免首页信息过载。
