# 第 0 步第三批｜教师端活动模块图片内容校验

> 分支：`delivery-html-business-prototype`  
> 范围：`效果图/教师手机端/2活动/`  
> 目标：校验教师端活动模块真实页面归属，建立后续 HTML 原型与业务逻辑说明的执行范围。活动模块包括：活动首页、教学反思、培训进修、企业实践、虚拟教研。

## 1. 校验口径

本批次继续沿用“不直接相信文件名”的原则，按以下顺序判断页面真实内容：

1. 底部 Tab 是否为“活动”；
2. 页面标题、返回标题、主卡片标题；
3. 页面里的业务对象是反思、培训、实践、教研室、教研活动，还是档案记录；
4. 页面是否产生可沉淀到成长档案的数据；
5. 页面是否需要管理端承接，例如培训需求、实践申请、教研贡献确认；
6. 页面是否只是误命名、历史版本或通用系统页。

> 当前 GitHub 连接器对 PNG 二进制内容无法稳定直接渲染，因此本批次先基于仓库路径、文件名线索和前期已确认的业务设计口径做结构化校验。文件名明显不可信的页面全部进入“需视觉复核”队列，不直接删除。

## 7. 本批次首批 HTML 建议范围

### 7.1 活动首页

- 活动首页；
- 活动首页含教研室入口状态，作为首页状态变体。

### 7.2 教学反思闭环

```text
教学反思开始方式
→ 选择反思依据 / 选择学期课程
→ 自主反思 / AI 引导对话
→ 反思报告草稿编辑
→ 确认成功
```

### 7.3 培训进修闭环

```text
培训进修首页
→ 提交培训需求
→ 我已找到想参加的培训
→ 培训需求提交结果
→ 培训总结
→ 培训材料归档提交结果
```

### 7.4 企业实践闭环

```text
企业实践年度概览
→ 企业实践年度列表
→ 提交实践计划
→ 确认提交
→ 计划通过 / 退回修改 / 修改计划
→ 实践进行中详情
→ 记录实践日志
→ 上传 / 补充实践证明
→ 归档提交结果
→ 企业实践记录已入档
```

同时，企业实践档案首页、概览、列表、详情复用到档案模块，补齐八维档案中的企业实践维度。

### 7.5 虚拟教研闭环

```text
我的教研室
→ 教研室邀请
→ 虚拟教研活动列表
→ 教研活动详情进行中
→ 阶段材料提交 / 补充材料
→ 待确认贡献
→ 贡献确认
→ 贡献确认已提交
→ 教研活动归档结果
→ 已归档贡献已确认
```

## 9. 业务校验点

1. **发展活动不是孤立功能，必须能沉淀成长档案**  
   教学反思、培训总结、企业实践材料、教研贡献确认都需要说明沉淀到哪个档案维度。

2. **AI 只生成草稿和整理建议**  
   教学反思 AI 对话、培训需求整理不能自动确认、自动归档或形成正式评价结论。

3. **培训需求提交后进入管理端需求管理**  
   教师提交需求不等于已纳入培训计划。

4. **企业实践是教师申请、部门同意**  
   不设计统一安排口径；进行中的实践不展示再次发起入口。

5. **虚拟教研先有教研室，再有教研活动**  
   教研室是组织容器，活动是协作与材料沉淀对象。

6. **腾讯会议结果应沉淀为教研记录**  
   会议完成后可形成研讨纪要、参会记录、材料附件，进入教研活动归档。

7. **贡献确认是明确业务动作**  
   贡献确认不是普通详情页操作，需要有确认提交和提交后状态。

## 10. 后续建议

教师端活动模块 HTML 不建议一次性全部制作，建议按以下顺序推进：

1. 活动首页；
2. 教学反思闭环；
3. 培训进修闭环；
4. 企业实践闭环；
5. 虚拟教研闭环；
6. 再处理误命名视觉复核队列。
