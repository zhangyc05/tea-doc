# 第 0 步第七批｜管理端 PC 能力画像模块图片内容校验

> 分支：`delivery-html-business-prototype`  
> 范围：`效果图/管理PC端/3能力画像/`  
> 目标：校验管理端能力画像模块真实页面归属，明确群体画像、教师画像查询、列表视图、教师个人画像之间的业务闭环，为后续 HTML 原型和开发交付说明打底。

## 1. 校验口径

本批次继续坚持：**不直接相信文件名，先按业务对象、分析层级和管理动作归类**。

判断顺序：

1. 左侧导航是否位于“能力画像”；
2. 页面分析对象是学校 / 院系 / 专业 / 教师个人，还是教师查询入口；
3. 页面是否基于能力清单执行版和正式档案事实；
4. 页面是否形成评价结论、排名或通过 / 不通过判断；
5. 页面是否能解释画像依据、短板位置、优势结构和支持方向；
6. 页面是否引导管理端进行合理支持，而不是直接形成强管理动作。

> 当前阶段不直接重命名图片，不移动原始 PNG，只把真实页面名、模块归属、交付范围和疑点记录到文档中。后续统一生成重命名清单。

## 5. 业务闭环校验

### 5.1 群体画像闭环

```text
能力清单执行版
→ 成长档案正式事实
→ 学校 / 院系 / 专业群体画像
→ 识别共性优势和短板
→ 形成资源配置和支持方向
→ 下钻教师画像查询
```

### 5.2 教师画像查询闭环

```text
群体画像下钻 / 直接搜索教师
→ 教师画像查询页
→ 卡片视图或列表视图
→ 选择教师
→ 教师个人画像详情
```

### 5.3 教师个人画像闭环

```text
教师正式档案事实
→ 四轴能力画像
→ 综合发展指数 / 发展特征
→ 画像依据解释
→ 支持方向
→ 回到培训、企业实践、虚拟教研、档案补充等已有业务路径
```

## 6. 页面业务说明要求

后续 HTML 页面中，每个页面都应附带业务说明区：

1. **群体画像 / 学校画像**  
   - 基于能力清单执行版和正式档案事实生成；
   - 用于发展分析和资源配置参考；
   - 不作为正式评价结论；
   - 不展示教师排名；
   - 观察范围应包含能力结构、短板分布、已有优势、数据完整性和支持方向。

2. **教师画像查询页**  
   - 是进入教师个人画像的先导页；
   - 卡片视图适合快速看教师类型和主要特征；
   - 列表视图适合检索、筛选和批量浏览；
   - 页面上不放无意义统计卡，避免增加认知负担。

3. **教师个人画像详情**  
   - 使用四轴雷达图：教学、教研、实践、服务；
   - 基本能力作为中心达标徽章，不作为雷达轴；
   - 展示发展特征，不使用“教师分类评价结论”；
   - 支持方向要可理解，例如培训、实践、教研支持、档案补充，不展示难以理解的管理术语；
   - 不扩展复杂后续动作，只保留查看管理支持方向。

4. **依据解释**  
   - 只引用正式档案事实；
   - 说明数据完整性和画像可信度；
   - 不引用待确认、线索、草稿记录；
   - 若数据不足，应明确提示“数据不足，建议补充档案”，而不是给出确定结论。

## 7. 风格与交互约束

1. 管理端继续使用浅色教育 SaaS 风格，不使用黑色侧边栏或深色大屏风格。
2. 不使用“全校教师能力画像”这类无增量主标题，面包屑和页面内容已经能表达页面对象。
3. 群体画像页面不要堆无意义统计卡，重点展示结构、短板、优势、数据完整性和支持方向。
4. 教师画像查询页必须先出现，不能直接进入林老师详情。
5. 教师个人画像页的“支持方向”要具体可理解，不能做成看不懂的抽象标签。
6. 画像只做解释和支持，不做排名、奖惩或通过 / 不通过判断。
