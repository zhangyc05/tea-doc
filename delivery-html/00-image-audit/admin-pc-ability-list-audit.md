## 1. 校验口径

本批次继续坚持：**不直接相信文件名，先按业务对象、页面状态和业务动作归类**。

判断顺序：

1. 左侧导航是否位于“能力清单”；
2. 面包屑是否区分执行版、基准模版、岗位 / 聘期要求映射；
3. 页面主对象是清单结构、指标编辑、优化建议、发布确认，还是映射规则；
4. 页面是否改变执行版状态；
5. 是否涉及 AI 生成建议，是否需要人工确认；
6. 是否会影响教师端画像、岗位 / 聘期对照、个人报告和档案缺口。

> 当前阶段不直接重命名图片，不移动原始 PNG，只把真实页面名、模块归属、交付范围和疑点记录到文档中。后续统一生成重命名清单。

## 3. 本批次产品取舍决策

| 问题 | 决策 | 后续执行方式 |
|---|---|---|
| 执行版和基准模版是否分开 | 分开 | 基准模版是母版 / 结构基础；执行版是某周期正式运行口径 |
| 执行版编辑是否单独成页 | 不单独成页 | 作为执行版查看页的右侧抽屉编辑态 |
| 基准模版优化建议是否两个页面都做 | 合并处理 | 保留优化流程，首批以建议结果态为主，另一个作为过程态 / 候选态 |
| 发布确认是否必做 | 必做 | 执行版发布影响教师端画像、报告、岗位 / 聘期对照，必须有确认页 |
| 岗位 / 聘期要求映射是否必做 | 必做 | 这是教师端目标岗位对照、聘期要求对照的规则来源 |
| 映射编辑是否单独成页 | 不单独成页 | 作为映射页右侧抽屉编辑态 |
| AI 优化建议能否直接生效 | 不能 | AI 只提供建议，管理员人工采纳后进入草稿或编辑态 |

## 5. 业务闭环校验

### 5.1 执行版闭环

```text
基准模版
→ 派生执行版
→ 执行版查看
→ 编辑指标
→ 发布确认
→ 发布执行版
→ 影响教师端画像 / 岗位对照 / 聘期要求对照 / 个人报告
```

### 5.2 基准模版优化闭环

```text
基准模版查看
→ 进行优化
→ AI 生成优化建议
→ 管理员人工采纳 / 忽略
→ 形成基准模版草稿
→ 后续派生执行版
```

### 5.3 岗位 / 聘期要求映射闭环

```text
制度要求 / 岗位要求 / 聘期要求
→ 映射到能力维度 / 要素 / 指标 / 证据类型
→ 编辑映射规则
→ 校验影响范围
→ 教师端目标岗位对照 / 聘期要求对照引用
```

## 6. 页面业务说明要求

后续 HTML 页面中，每个页面都应附带业务说明区：

1. **执行版查看页**  
   - 展示当前正式运行口径；
   - 明确适用周期和适用对象；
   - 说明该版本被能力画像、岗位 / 聘期对照、个人报告引用；
   - 已发布版本不允许直接覆盖修改。

2. **执行版指标编辑抽屉**  
   - 只编辑必要字段；
   - 保存后先进入草稿 / 待发布状态；
   - 变更需要重新校验引用影响；
   - 抽屉应遮盖页面内容，不做左右分栏。

3. **执行版发布确认**  
   - 重点说明影响范围；
   - 不需要复杂长步骤条；
   - 校验失败只列摘要和跳转入口。

4. **基准模版查看页**  
   - 展示维度、要素、指标结构；
   - 不直接作用于教师端；
   - 作为生成执行版的基础。

5. **基准模版优化建议**  
   - 按“进行优化”表达，不用生硬的“生成优化建议”作为主操作；
   - AI 建议需要人工采纳；
   - 建议来源可包括制度文件和运行数据，但不能自动覆盖基准模版。

6. **岗位 / 聘期要求映射页**  
   - 左侧可展示制度要求 / 岗位要求 / 聘期要求；
   - 右侧映射到能力指标、证据类型和计算规则；
   - 使用“计算规则”，不使用“依据规则”；
   - 该页支撑教师端目标岗位对照和聘期要求对照。

## 7. 风格与交互约束

1. 管理端继续使用浅色教育 SaaS 风格，不使用黑色侧边栏或深色大屏风格。
2. 左侧导航应展开二级菜单，能力清单下区分执行版、基准模版、岗位 / 聘期要求映射等入口。
3. 编辑类动作优先使用右侧抽屉，抽屉直接覆盖页面内容，而不是左右布局。
4. 不增加“系统参考模板”入口；当前口径使用“基准模版”。
5. 页面内容必须有明确理由，无法解释的字段、按钮和模块不进入 HTML。
