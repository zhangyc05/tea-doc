# 第 0 步第八批｜管理端 PC 发展活动模块图片内容校验

> 分支：`delivery-html-business-prototype`  
> 范围：`效果图/管理PC端/4发展活动/`  
> 目标：校验管理端发展活动模块真实页面归属，明确教学反思、培训管理、企业实践、虚拟教研四类活动的管理闭环，为后续 HTML 原型和开发交付说明打底。

## 1. 校验口径

本批次继续坚持：**不直接相信文件名，先按业务对象、处理状态和管理承接关系归类**。

判断顺序：

1. 左侧导航是否位于“发展活动”；
2. 二级模块是教学反思、培训管理、企业实践还是虚拟教研；
3. 页面主对象是活动记录、需求、资源、申请、计划、详情，还是贡献确认；
4. 页面是否改变教师端活动状态，例如提交、待核验、已入档、退回补充、已确认贡献；
5. 页面是否沉淀成长档案事实；
6. 页面是否支撑能力画像中的短板支持方向；
7. 页面是否出现不必要的审批、评价或管理复杂度。

> 当前阶段不直接重命名图片，不移动原始 PNG，只把真实页面名、模块归属、交付范围和疑点记录到文档中。后续统一生成重命名清单。

## 9. 业务闭环校验

### 9.1 教学反思闭环

```text
教师端保存 / 确认教学反思
→ 管理端教学反思概览
→ 查看反思详情
→ 沉淀个人发展 / 教学工作相关记录
→ 为能力画像和个人报告提供依据
```

### 9.2 培训管理闭环

```text
能力画像观察 / 教师主动提出
→ 培训需求管理
→ 资源库筛选资源
→ 教师申请处理
→ 培训组织 / 计划附属流程
→ 教师完成培训并补总结 / 证书
→ 记录总览 / 记录详情
→ 成长档案入档
```

### 9.3 企业实践闭环

```text
年度实践要求 / 画像短板观察
→ 年度实践跟踪
→ 教师发起企业实践申请
→ 管理端申请处理
→ 教师开展实践并补材料
→ 实践记录总览
→ 核验后入档
```

### 9.4 虚拟教研闭环

```text
教研室管理
→ 教研活动管理
→ 腾讯会议 / 材料 / 纪要沉淀
→ 教师贡献确认
→ 研讨记录 / 贡献记录
→ 已确认贡献入档
```

## 10. 页面业务说明要求

1. **教学反思管理**  
   - 管理端只查看反思沉淀情况；
   - 不设置审核通过 / 不通过；
   - 不给教师端造成“反思被评分”的压力。

2. **培训管理**  
   - 二级菜单采用：记录总览、需求管理、资源库、申请处理；
   - 资源库统计资源本身；
   - 需求来源只保留能力画像观察、教师主动提出；
   - 申请处理只判断是否纳入培训名单；
   - 计划相关页面作为附属流程，不作为主菜单入口。

3. **企业实践管理**  
   - 不设计统一安排；
   - 管理端提醒和处理申请，教师端发起实践；
   - 实践证明以附件资料为主，不强制企业评价。

4. **虚拟教研管理**  
   - 先管理教研室，再管理教研活动；
   - 腾讯会议结果沉淀为活动记录；
   - 贡献确认是明确业务动作，不能和普通详情混淆。

## 11. 风格与交互约束

1. 管理端继续使用浅色教育 SaaS 风格，不使用黑色侧边栏或深色大屏风格。
2. 发展活动模块避免“审核中心”式压迫感，更多表达为记录、处理、确认、归档。
3. 页面内容必须有明确业务理由，无必要统计卡、重复入口、不可解释字段不进入 HTML。
4. AI 只能生成建议、草稿或整理材料，不能自动审核、自动入档或形成正式评价结论。
5. 活动产生的数据必须说明是否入档、入哪个维度、是否作为画像和报告依据。
