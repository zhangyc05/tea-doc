# 第 0 步第六批｜管理端 PC 成长档案模块图片内容校验

> 分支：`delivery-html-business-prototype`  
> 范围：`效果图/管理PC端/2成长档案/`  
> 目标：校验管理端成长档案模块真实页面归属，明确部门资料导入、后台识别、识别完成、档案处理、来源详情、档案查阅、阅读档案详情之间的业务闭环，为后续 HTML 原型和开发交付说明打底。

## 1. 校验口径

本批次继续坚持：**不直接相信文件名，先按业务对象、数据状态和处理动作归类**。

判断顺序：

1. 左侧导航是否位于“成长档案”；
2. 页面主对象是导入批次、资料识别、候选记录、档案处理、来源详情，还是教师档案查阅；
3. 页面是否改变档案记录状态，例如线索、待确认、正式、异常、纠错中、已更正、已复用；
4. 页面是否需要教师端确认、补充或纠错承接；
5. 页面是否会为能力画像、岗位 / 聘期对照、个人报告提供正式档案事实；
6. 是否出现会增加管理负担或教师理解成本的冗余入口。

> 当前阶段不直接重命名图片，不移动原始 PNG，只把真实页面名、模块归属、交付范围和疑点记录到文档中。后续统一生成重命名清单。

## 5. 业务闭环校验

### 5.1 部门资料导入闭环

```text
部门上传资料
→ 创建导入批次
→ 后台识别中
→ 识别完成
→ 生成待处理记录 / 异常记录
→ 档案处理
→ 教师确认或管理端核验
→ 正式入档
→ 支撑画像、岗位 / 聘期对照、个人报告
```

### 5.2 档案处理闭环

```text
部门上传 / 公开线索 / 系统识别记录
→ 待处理记录
→ 查看来源详情
→ 匹配教师与档案维度
→ 确认入档 / 发给教师确认 / 标记异常 / 退回补充
→ 状态留痕
```

### 5.3 档案查阅闭环

```text
选择教师
→ 查看八维档案概括
→ 下钻维度记录
→ 阅读档案详情
→ 查看来源、状态、引用、纠错记录
→ 必要时发起纠错处理或补充材料
```

## 6. 页面业务说明要求

后续 HTML 页面中，每个页面都应附带业务说明区：

1. **导入部门资料｜上传资料页**  
   - 上传的是部门已有资料，不要求用户在第一步判断资料细类；
   - 上传后进入后台识别；
   - 不需要“下载示例模板”作为主操作；
   - 不放无必要的基本信息区。

2. **导入批次详情｜识别中**  
   - 明确识别为异步后台处理；
   - 展示批次名称、上传时间、处理进度、已识别数量、异常数量；
   - 不提供需要用户重复点击的“开始识别”动作。

3. **导入批次详情｜识别完成**  
   - 展示识别结果，不表示正式入档；
   - 区分可处理记录、异常记录、需人工判断记录；
   - 提供进入档案处理的路径。

4. **档案处理**  
   - 来源筛选使用“部门上传 / 公开线索 / 系统识别”等清楚表达；
   - 不使用“外部结果”；
   - 处理动作应轻量，围绕确认、退回、发给教师确认、标记异常。

5. **来源详情**  
   - 展示来源文件、识别字段、匹配教师、匹配置信度、处理记录；
   - 作为下钻详情或右侧抽屉，避免增加页面层级。

6. **教师档案查阅**  
   - 先展示教师八维档案概括；
   - 再提供查看记录入口；
   - 不把当前维度记录列表直接作为主内容。

7. **阅读档案详情**  
   - 展示记录正文、来源、状态、入档时间、引用去向、纠错记录；
   - 能说明该记录是否被画像、岗位 / 聘期对照、个人报告引用。

## 7. 风格与交互约束

1. 管理端继续使用浅色教育 SaaS 风格，不使用黑色侧边栏或深色大屏风格。
2. 导入和处理流程要体现后台异步，不做同步假象。
3. 页面内容必须有明确业务理由，没有稳定依据的字段、按钮和模块不进入 HTML。
4. 管理端可以使用“候选记录 / 系统识别记录”，但教师端必须转译为“待确认记录 / 待确认材料”。
5. 档案状态要可追踪，不能只展示结果、不保留处理过程。
