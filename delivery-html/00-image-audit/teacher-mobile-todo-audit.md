## 4. 发现的业务校验点

1. **待办和系统消息必须分开**  
   待办承接待确认、待补充、可完善事项；铃铛进入系统消息，不进入全部待办。

2. **待办文案必须是具体动作**  
   例如“确认一条培训证书”“完善一篇教学反思”，不使用“补齐聘期要求证明缺口”这类宽泛表达。

3. **教师端不使用“候选数据”**  
   待确认培训证书应表达为“系统已帮您识别，请确认是否属于本人”。

4. **确认入档和修改提交是两条不同状态线**  
   - 确认入档：待确认 → 正式入档；
   - 修改提交：待确认 → 待核验，不应直接正式入档。

5. **“不是我的”处理结果已确认**  
   `4-3不是我的.png` 是“已移出待确认页”，不是二次确认页。后续 HTML 中需要表达为处理完成结果页。

6. **搜索无结果页已移入档案模块**  
   `5-1搜索档案-没有相关记录.png` 虽在待办目录，但按真实业务对象归入教师端档案模块。

7. **全部动态保留在待办模块内**  
   全部动态展示教师最近完成、保存或系统记录的成长动态，不展示系统消息，也不作为待处理事项列表。

8. **第一批 HTML 样板范围已确认**  
   第一批 HTML 以“成长档案待确认记录闭环”为样板先做，先跑通教师端待确认记录的确认、编辑、待核验、移出待确认等状态。
