# 第 0 步｜效果图内容校验工作台

本目录用于整理教师综合发展平台效果图的真实页面内容，先校验“文件名”和“图片内容”是否一致，再进入 HTML 原型还原和业务逻辑说明。

## 一、当前原则

1. 不以图片文件名直接判断页面内容。
2. 先逐张识别图片中的真实标题、导航、菜单选中项、主卡片、表格字段、按钮和状态标签。
3. 对每张图建立“原始路径 → 真实页面 → 业务归属 → 是否进入交付”的校验记录。
4. 只有通过校验的页面，才进入后续 HTML 原型交付。
5. 同一页面存在多个版本时，先标记为“版本冲突 / 待审核”，不直接选择最终稿。

## 二、校验表字段

| 字段 | 说明 |
|---|---|
| 原始路径 | 仓库中的图片路径 |
| 原文件名 | 当前图片文件名，仅作线索 |
| 图片识别标题 | 从图片顶部标题、面包屑、导航或主区域识别出来的标题 |
| 真实页面内容 | 图片实际展示的页面内容摘要 |
| 实际所属端 | 教师手机端 / 管理 PC 端 |
| 实际所属模块 | 待办 / 档案 / 活动 / 我的 / AI 助手 / 能力清单 / 成长档案 / 培训管理等 |
| 页面类型 | 首页 / 列表 / 详情 / 表单 / 结果页 / 抽屉 / 弹窗 / 状态页 |
| 文件名是否匹配 | 匹配 / 部分匹配 / 不匹配 |
| 建议页面名 | 基于图片真实内容重新命名 |
| 是否进入交付 | 必做 / 待确认 / 暂不进入 |
| 需要审核的问题 | 业务逻辑、字段、状态、归属或版本问题 |

## 三、第 0 步产出物

- `image-audit.csv`：逐图校验表，便于筛选和审核。
- `image-audit-notes.md`：校验过程中的问题说明。
- `page-map-draft.md`：基于真实图片内容形成的页面地图草案。

## 四、提交节奏

- 第一次提交：建立第 0 步工作台目录和校验规则。
- 后续提交：按模块提交校验结果，例如教师端待办、教师端档案、教师端活动、管理端成长档案、管理端培训管理等。
- 每批校验完成后先提交到当前工作分支，等待人工审核后再进入 HTML 原型还原。
