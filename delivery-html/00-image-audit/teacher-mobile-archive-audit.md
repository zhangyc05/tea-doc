# 第 0 步第二批｜教师端档案模块图片内容校验

> 分支：`delivery-html-business-prototype`  
> 范围：`效果图/教师手机端/1档案/`，并承接上一批已确认移入档案模块的 `效果图/教师手机端/0待办/5-1搜索档案-没有相关记录.png`。  
> 目标：先校验图片真实业务归属、页面类型、是否进入交付和命名风险，再进入 HTML 原型还原。

## 1. 校验口径

本批次不直接相信文件名，按以下顺序判断页面真实内容：

1. 页面顶部标题、返回标题、底部 Tab 选中项；
2. 页面主卡片标题、字段组、状态标签、按钮文案；
3. 是否属于教师端成长档案的查看、搜索、分类、详情、纠错、更正、补充材料或入档结果；
4. 是否与管理端成长档案处理、纠错处理、档案查阅存在承接关系；
5. 是否属于通用系统页面或历史误命名页面。

> 重要说明：由于当前仓库中的图片命名存在不可靠情况，本表以“真实业务对象和页面功能”作为归类依据；文件名只作为资产定位线索。对于明显可能是误命名的图片，先标为“需视觉复核”，不直接排除。

## 4. 发现的业务校验点

1. **档案首页只能承接档案查看和查询，不承接系统消息或待办处理**  
   待办入口已经在第一批保留，档案首页重点是正式档案与档案查询。

2. **维度页优先做“概括”，不是直接铺记录列表**  
   教学工作、教研科研、个人发展等维度页应先说明该维度下的当前概况，再提供查看记录入口。

3. **同一页面多个版本必须收敛**  
   教学工作概览、教学工作列表、基本信息详情、教研记录详情存在多个版本，开发交付前只能保留最终版本。

4. **纠错更正闭环必须保留**  
   职称聘用更正、已提交、待核验、已补充、补充材料、结果页是档案纠错闭环关键状态，建议进入首批档案 HTML。

5. **教师端避免管理化页面语义**  
   角色权限管理、访问权限页面、活动项目管理、会话管理页面、绩效管理页面等文件名不能直接作为教师端页面名称，需要复核真实内容并转译为教师可理解的页面名。

6. **正式档案、待确认记录、草稿记录要区分**  
   档案模块展示正式档案为主；待确认记录在待办闭环处理；“档案草稿”是否存在，需要业务确认。

## 6. 对后续 HTML 的建议

档案模块不要一次性全量还原，建议先做一条“正式档案查看 + 纠错更正”闭环：

```text
档案首页
→ 档案搜索 / 搜索无结果
→ 最近入档
→ 八维分类入口
→ 教学工作概览
→ 教学工作记录列表
→ 教学评价记录详情
→ 职称聘用更正申请
→ 更正申请已提交
→ 更正进度 / 补充材料 / 更正结果
```

这条闭环能同时验证：正式档案查看、记录下钻、空状态、纠错更正、管理端承接。
