# 02｜设计系统风格升级任务清单

> 目标：把当前 `/design-system` 从 Token 展示页升级为「清朗可信教育治理 SaaS」风格决策系统，支撑后续高保真效果图稳定转成 Vue 页面。

## 一、任务总览

### T1｜明确项目风格画像｜已完成
- 输出项目级风格定义：清朗可信教育治理 SaaS。
- 固定产品气质：可信、清朗、克制、专业、低认知负担。
- 明确适合风格：Minimalism & Swiss Style、Accessible & Ethical、Soft UI Evolution、Dimensional Layering、Bento Box Grid、Drill-Down Analytics Dashboard。
- 明确禁止风格：暗黑大屏、赛博朋克、AI 紫粉渐变、营销页、厚重玻璃拟态、无依据炫技图表。

### T2｜沉淀风格组合方案｜已完成
- 将风格选择拆成主风格、辅助风格、页面组织方式、分析页组织方式。
- 给出每种风格在本项目中的使用边界。
- 避免把项目误定义为“浅色薄荷绿风格”。

### T3｜建立反模式库｜已完成
- 明确哪些设计会导致项目跑偏。
- 覆盖颜色、导航、AI、图表、动效、术语、教师端/管理端信息密度等规则。
- 作为后续 AI 生成页面和人工开发的检查依据。

### T4｜建立页面模式库｜已完成
- 管理端列表页模式。
- 管理端分析页模式。
- 教师 PC 工作台模式。
- 手机端卡片页模式。
- AI 助理浮层模式。
- 每种模式说明适用场景、结构、组件组合、关键规则和禁止事项。

### T5｜建立交付检查清单｜已完成
- 检查页面是否使用统一 Token。
- 检查是否复用 Layout / common 组件。
- 检查是否存在硬编码颜色、暗色侧栏、emoji 图标、营销页风格。
- 检查管理端、教师 PC、手机端的信息密度是否符合各自场景。
- 检查是否通过 typecheck/build 和截图对比。

### T6｜升级设计系统页面导航｜已完成
- 在 `/design-system` 中新增：项目风格画像、页面模式、反模式、交付检查。
- 移除导航中的 emoji 表达，改为更正式的文本栏目。
- 保留颜色、字体、尺寸、组件展示等已有能力。

### T7｜升级内容渲染组件｜已完成
- 为项目风格画像新增展示组件。
- 为页面模式新增展示组件。
- 为反模式新增展示组件。
- 为交付检查新增展示组件。
- 使用现有 Token 和浅色教育 SaaS 后台风格展示，不另起一套视觉风格。

### T8｜后续页面转 Vue 的执行规则｜待后续页面实现时执行
- 每张效果图先匹配页面模式。
- 再根据页面模式选择组件组合。
- 页面实现后按交付检查清单验收。
- 新沉淀出的复用组件再补回设计系统。

本批次已完成 T1 - T7 的最小可用版本：

- 已新增风格画像数据。
- 已新增风格组合数据。

- 已新增页面模式数据。

## 三、验收标准

- `/design-system` 可看到「项目风格画像 / 页面模式 / 反模式 / 交付检查」。
- 新栏目内容围绕教师综合发展平台，不泛化成普通 SaaS。
- 不使用“浅色薄荷绿”作为项目风格名称。
- 不引入新的大型 UI 库。
- 不破坏已有颜色、字体、尺寸、组件展示能力。
- 代码结构可继续支撑后续页面模式扩展。
