# 05｜本地截图验收规则

## 1. 验收定位

页面验收以本地运行截图和目标效果图对比为准。

目标效果图是桌面视觉基准，不是唯一固定视口。验收重点是结构、比例、密度、层级和响应式稳定性，而不是把页面锁死在目标图原始像素尺寸。

页面未完成截图对比前，不得标记为视觉验收通过。

## 2. 本地启动

```bash
cd frontend
npm install
npm run dev
```

页面地址以页面台账为准。

资源库页面当前地址：

```txt
http://localhost:5173/admin/training/resources
```

## 3. 截图视口

每个桌面页面至少完成以下视口截图：

```txt
1. 1280 × 800：窄桌面底线，检查是否溢出或拥挤；
2. 1440 × 900：常见桌面；
3. 1536 × 864：常见笔记本；
4. 1920 × 1080：宽桌面。
```

如目标效果图有明确原始尺寸，可以额外增加同尺寸截图作为参考，但不得只验收该单一尺寸。

## 4. 截图要求

截图时应保持：

```txt
1. 浏览器缩放 100%；
2. deviceScaleFactor 固定为 1；
3. 页面完整显示左侧导航、顶部栏、主内容；
4. 不使用移动端模拟；
5. 不裁掉右侧栏或分页区；
6. 保持同一浏览器和同一字体环境；
7. 每个视口截图文件名应包含页面名、视口宽高和时间或轮次。
```

## 5. 对比维度

每次截图对比必须检查：

```txt
1. 页面整体布局；
2. 左侧导航；
3. 顶部栏；
4. 面包屑和标题；
5. 统计卡；
6. 筛选区；
7. 主表格；
8. 右侧概览；
9. 分页；
10. 颜色、圆角、阴影、密度；
11. 统计卡、筛选区、表格、右侧栏在不同宽度下的换行和伸缩；
12. 是否存在文字重叠、按钮溢出、表格列被压扁、右侧栏被裁切。
```

## 6. 差异记录

如果截图不一致，应按视口记录差异清单：

```txt
视口尺寸
差异位置
目标效果
当前效果
修正方式
是否已完成
```

差异修正必须优先处理结构和可用性问题：

```txt
1. 内容溢出、重叠、裁切；
2. 页面区域缺失或位置错误；
3. 关键比例明显偏离；
4. 表格密度、行高、列宽异常；
5. 颜色、圆角、阴影、图标等细节差异。
```

## 7. 验收状态

页面台账中的验收状态只能使用：

```txt
未开始
开发中
待本地截图
截图待修正
视觉验收通过
```

## 8. 通过标准

标记为“视觉验收通过”前，必须同时满足：

```txt
1. 所有必验桌面视口已截图；
2. 页面结构、比例、密度与目标效果图一致或有明确响应式调整理由；
3. 无文字重叠、控件溢出、表格压扁、右侧栏裁切；
4. 关键业务字段和操作与目标效果图一致；
5. 差异清单中没有未处理的 P0/P1 视觉或可用性问题。
```

## 9. 继续开发门槛

样板页未通过视觉验收前，不进入后续同类页面开发。

资源库页面是当前管理端样板页，必须先完成视觉验收，再进入需求管理、申请处理、记录总览等页面。
