# 04｜页面还原规则

## 1. 页面还原目标

页面还原的目标是让本地运行页面在结构、层级、密度和主要视觉语言上接近目标效果图。

不能只以“页面能打开、数据能显示、按钮能点击”为完成标准。

## 2. 还原前置条件

开始写 Vue 前，必须已经完成：

```txt
1. 效果图识别结果
2. 页面区域拆解
3. 组件提炼清单
4. mock 字段清单
5. 页面验收点
```

## 3. 页面结构还原要求

必须先还原大结构，再还原细节。

顺序固定为：

```txt
1. 页面壳：侧栏、顶部栏、内容区宽度
2. 页面主结构：上方统计、主内容、右侧辅助栏
3. 业务模块：筛选、列表、概览、分页
4. 细节：状态、图标、间距、圆角、阴影
5. 交互：筛选、详情、分页、按钮
```

## 4. mock 数据要求

mock 必须集中放在 `src/mock/` 下。

页面内不得散落大段 mock 数据。

mock 字段必须服务目标效果图，不为了填满页面新增无依据字段。

## 5. 操作实现要求

```txt
1. 已明确交互的操作可以实现。
2. 未明确交互的操作可以静态展示，但不能误导为已实现。
3. 无业务必要的操作不出现。
4. 页面主操作必须和效果图一致。
```

## 6. 视觉还原要求

每个页面必须检查：

```txt
1. 左侧导航是否与目标图一致；
2. 顶部栏是否与目标图一致；
3. 页面标题和面包屑层级是否一致；
4. 统计卡结构是否一致；
5. 筛选区行数和字段是否一致；
6. 表格字段和密度是否一致；
7. 右侧栏是否存在且结构一致；
8. 分页是否存在且结构一致；
9. 状态标签是否符合目标图；
10. 页面是否有明显空白或拥挤。
```

## 7. 提交前检查

提交前必须确认：

```txt
1. 是否更新页面台账；
2. 是否记录本地截图验收状态；
3. 是否新增了无依据字段；
4. 是否存在未实现空按钮；
5. 是否影响其他已验收页面。
```
