# 03｜组件提炼规则

## 1. 基本原则

组件必须从目标效果图中提炼。

禁止先设计通用组件，再强行拼装页面。

组件提炼顺序：

```txt
页面区域 → 模块结构 → 字段和状态 → 交互行为 → 组件边界 → Vue 文件
```

## 2. 组件分类

### 2.1 页面壳组件

用于承载全局布局：

```txt
AdminShell / AdminLayout
AdminSidebar
AdminTopbar
AppBreadcrumb
FloatingAIAssistant
```

### 2.2 页面业务组件

只服务当前业务模块，但可以在同模块复用：

```txt
ResourceMetricCard
ResourceFilterPanel
ResourceTable
ResourceOverviewPanel
ResourceDistributionList
ResourcePagination
ResourceDetailSheet
```

### 2.3 基础 UI 组件

只承载基础样式，不承载业务判断：

```txt
Button
Card
Table
Input
Select
Badge
Sheet
```

## 3. 组件提炼判断

满足任一条件，可以提炼为组件：

```txt
1. 在目标效果图中形成清晰独立区域；
2. 有稳定字段结构；
3. 后续同类页面可能复用；
4. 需要独立交互；
5. 会影响页面视觉基准。
```

不满足以上条件时，不要过度组件化。

## 4. 组件说明必须包含

每个组件提炼时必须写清：

```txt
组件名称
来自效果图的哪个区域
组件职责
输入 props
输出 events
内部字段
是否依赖 mock
是否可复用
视觉关键点
```

## 5. 资源库页面组件候选

资源库页面应优先提炼以下组件：

```txt
AdminSidebar
AdminTopbar
MetricIconCard
ResourceFilterPanel
ResourceTable
ResourceOverviewPanel
ResourceDistributionList
PaginationBar
ResourceDetailSheet
FloatingAIAssistant
```

## 6. 旧组件使用原则

已有组件可以复用，但必须满足目标效果图要求。

如果已有组件无法表达目标效果图结构，应新增业务组件或升级组件，而不是强行使用。
