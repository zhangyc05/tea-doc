# 管理端企业实践模块｜第一批粗实现任务

## 1. 任务目标

根据用户上传的 `3企业实践.zip` 中 3 张效果图，实现管理端 PC「企业实践」模块第一批页面。

本批继续采用粗实现策略：先完成页面内容、路由和基础交互，后续再统一做视觉精修。

```txt
年度实践跟踪
实践申请处理
实践记录总览
```

文字模型不能识别图片，因此实现时必须以本文档为准，不得根据页面名称自由设计。

## 2. 当前仓库边界

当前左侧菜单已有：

```txt
企业实践
- 年度实践跟踪
- 申请处理
- 记录总览
```

本批不要修改左侧菜单结构。

当前已有路由：

```txt
/admin/practice/tracking
/admin/practice/applications
/admin/practice/records
```

这些路由当前仍是占位页，需要替换为真实页面。

## 3. 新增页面文件

```txt
frontend/src/pages/admin/practice/PracticeTrackingPage.vue
frontend/src/pages/admin/practice/PracticeApplicationPage.vue
frontend/src/pages/admin/practice/PracticeRecordPage.vue
```

## 4. 路由修改

修改：

```txt
frontend/src/router/admin.routes.ts
```

新增 lazy import：

```ts
const PracticeTrackingPage = () => import('@/pages/admin/practice/PracticeTrackingPage.vue')
const PracticeApplicationPage = () => import('@/pages/admin/practice/PracticeApplicationPage.vue')
const PracticeRecordPage = () => import('@/pages/admin/practice/PracticeRecordPage.vue')
```

路由映射：

```txt
/admin/practice/tracking      → PracticeTrackingPage.vue
/admin/practice/applications  → PracticeApplicationPage.vue
/admin/practice/records       → PracticeRecordPage.vue
```

menuKey：

```txt
practice-tracking
practice-applications
practice-records
```

所有页面都必须包裹 `AdminLayout`，并使用对应 active-key。

## 5. 通用要求

```txt
使用 AdminLayout。
保持蓝白教育治理 SaaS 风格。
优先复用 admin-card、admin-table、badge-status、btn-primary、btn-secondary、btn-link。
全部使用页面内 mock 数据。
不接后端接口。
本批只做粗实现，不做视觉精修。
```

业务边界：

```txt
企业实践管理不是统一安排实践，而是识别需要实践的教师、处理教师实践申请、跟踪实践完成情况、查看实践记录。
实践记录进入成长档案 / 企业实践维度。
```
