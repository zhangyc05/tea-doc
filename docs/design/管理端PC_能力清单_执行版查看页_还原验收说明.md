## 一、还原目标

将仓库中的目标效果图：

```text
效果图/管理PC端/1能力清单/管理端PC｜能力清单｜执行版查看页.png
```

还原到 Vue 页面：

```text
/admin/ability-list/execution
```

当前还原策略：

- 1920 效果图作为视觉参考和客户演示参考；
- Vue 页面按真实产品方式响应式实现，不再按 1920 固定尺寸硬编码；
- 14 寸 Mac 笔记本是主力办公口径，应保证页面自然收缩、业务内容优先；
- 文字和字段以 `docs/design/管理端PC_能力清单_执行版查看页_内容校准基准.md` 为准；
- 右侧插画使用 Vue 内嵌 SVG 近似还原，空间不足时应弱化或隐藏，不应挤压业务内容。

## 三、响应式布局口径

### 大屏 / 演示口径

- 参考目标：1920 × 1080 效果图
- 用途：客户演示、大屏展示、视觉还原参考
- 特征：横幅插画完整展示，卡片间距更舒展

### 14 寸 Mac / 主力办公口径

- 常见 CSS 视口宽度：约 1440px ～ 1512px，取决于系统缩放和浏览器窗口
- 用途：日常管理端办公
- 特征：侧栏、顶部栏、横幅、字号和表格行高自动收缩
- 原则：表格和业务信息优先，插画不应抢占主要空间

### 紧凑办公口径

- 小于约 1280px 时，页面保留横向可读性
- 业务表格允许横向滚动
- 插画可隐藏

## 四、本地验收步骤

```bash
cd frontend
npm install
npm run dev
```

打开：

```text
/admin/ability-list/execution
```

建议分别检查：

```text
1920 × 1080：是否接近效果图视觉方向
1512 × 982：是否适合 14 寸 Mac 默认显示
1440 × 900：是否仍然可办公
1280 × 800：是否允许紧凑展示和横向滚动
```

---

## 五、第一轮人工验收重点

1. 左侧导航是否随屏幕宽度自然收缩；
2. 顶部栏高度、筛选框、消息和头像是否不过大；
3. 执行版横幅是否在 14 寸 Mac 下不过高；
4. 标题是否控制在 1～2 行，不应出现明显压迫感；
5. 右侧插画是否服务于视觉，不应挤压核心信息；
6. 能力结构卡与指标矩阵卡比例是否协调；
7. 表格列宽、行高、状态标签、编辑入口是否清晰；
8. 页面文字是否与内容校准基准一致。

---

## 六、后续像素级增强建议

如需进一步逼近目标图，可增加 Playwright 截图对比流程：

1. 安装 Playwright；
2. 分别固定 viewport 为 1920 × 1080、1512 × 982、1440 × 900；
3. 截取 `/admin/ability-list/execution`；
4. 与目标图和人工验收截图进行差异比对；
5. 按差异调整 CSS。

当前阶段优先保证真实产品可用性，不以 1920 效果图的单一尺寸作为唯一标准。
