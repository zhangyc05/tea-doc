## 一、端口定位与角色边界

### 1.1 端口定位

管理端是面向组织范围和业务责任的处理与分析工作空间。页面围绕“我负责的范围内有哪些待处理事项、依据是什么、如何处理与下钻”组织，服务于部门协同、业务审核和管理决策。

管理端不是教师个人办理空间，也不是平台运维控制台。管理人员可核查业务材料和线索，但系统配置发布、同步任务重试和底层日志处置属于系统管理端能力。

### 1.2 共享布局下的角色差异

| 角色 | 默认范围 | 首屏重点 | 可用动作边界 |
| --- | --- | --- | --- |
| 部门管理者 | 本部门教师与待办 | 待审核、异常、逾期与教师级明细 | 处理本部门事项、要求补充、转交或查看明细 |
| 业务主管部门 | 授权业务条线/跨部门范围 | 业务队列、规则口径下的处理情况与质量汇总 | 业务审核、跨部门处理、汇总下钻；是否具备特定批量动作按授权展示 |
| 校级领导 | 全校汇总或授权范围 | 趋势、结构和管理摘要 | 原则上只读查看、筛选和下钻，不处理单条审核事项 |

相同页面模式可以复用结构，但必须通过当前范围标识、权限说明、可见操作和数据颗粒度表达角色差异。不得因共享布局而默认扩大任何角色的数据范围或操作能力。

### 1.3 设计原则

| 原则 | 设计要求 |
| --- | --- |
| 范围先行 | 页面始终清晰展示当前组织、业务条线、批次或时间范围。 |
| 待办可扫描 | 待处理对象、风险状态和处理优先级应便于快速定位。 |
| 依据伴随处理 | 审核、认定或异常处理前可直接查看来源、材料、匹配依据和历史记录。 |
| 权限显性 | 角色不具备的处理动作应隐藏或以只读说明表达，不能提供无效入口。 |
| 分析可下钻 | 汇总结论必须能落到明确范围或记录，避免只展示装饰性图表。 |
| 业务与运维分离 | 管理端只处理业务事项，不承担底层任务、发布和系统审计操作。 |

## 二、固定壳层与空间组织

### 2.1 壳层总结构

管理端采用 `tea-work` 业务端壳层和高密度但可扫描的处理工作区，强调筛选、列表与详情之间的连续操作。该壳层与系统管理端深色运维侧栏严格区分。

```text
顶部品牌栏：海洋蓝渐变品牌区域 / 当前学期或时间范围 / 当前管理身份与账户
左侧白色业务导航：分组业务入口 / 当前选中项海洋蓝高亮
内容上下文栏：当前位置 / 当前组织或业务授权范围
页面标题与操作区：页面任务 / 范围说明 / 页面级主操作
筛选与摘要区：范围筛选 / 状态筛选 / 事实型摘要
主工作区：列表或主图 / 选中对象详情与处理区
记录与辅助区：审核记录、来源依据、下钻提示或说明
```

### 2.2 区域职责

| 区域 | 固定职责 | 设计约束 |
| --- | --- | --- |
| 顶部品牌栏 | 提供系统识别、学期/时间语境和当前身份 | 使用海洋蓝渐变与白字，不承载系统环境或服务状态 |
| 左侧业务导航 | 在授权的业务管理入口之间切换 | 使用白底分组菜单和蓝色选中态，只展示管理业务能力 |
| 内容上下文栏 | 持续显示当前位置和授权范围 | 切换范围必须可感知，并影响列表/图表内容 |
| 筛选区 | 缩小当前处理或分析对象集合 | 优先放置范围、状态、时间、业务类型等高价值筛选 |
| 指标摘要 | 给出当前范围的事实型处理摘要 | 控制数量；指标需有口径和可下钻对象 |
| 主列表/主图 | 承载扫描、比较与定位 | 审核优先列表；分析优先一张主图与下钻表 |
| 详情处理区 | 查看证据并执行授权操作 | 可使用右栏或抽屉；操作随角色与状态变化 |
| 处理记录区 | 展示历史处理和留痕 | 服务于业务追溯，不扩展为系统审计控制台 |

### 2.3 `tea-work` 视觉 Token 继承

| 类别 | 管理端应用规则 |
| --- | --- |
| 品牌主色 | 主操作与选中态使用 `#1a5f8a`，深色强调使用 `#154161`，浅色激活底使用 `#e6f7ff` |
| 顶部栏 | 使用 `#64b5f6` 至 `#42a5f5` 的蓝色渐变和白色内容 |
| 工作区 | 页面背景 `#f0f2f5`，卡片背景 `#ffffff`，边框以 `#d9d9d9` / `#e8e8e8` 为基准 |
| 文本与字体 | 正文使用 `#262626`、辅助信息使用 `#595959` / `#8c8c8c`；字体优先 `Noto Sans SC`、`Microsoft YaHei` |
| 密度与圆角 | 常规控件以 `13px` 正文、`4px` 基础圆角呈现；主要内容卡可使用 `8px` 至 `12px` 圆角和轻阴影 |

HTML 验证页复现上述风格特征，不直接复制项目源码、字体资源或业务数据。

### 2.4 信息密度与页面重心

| 页面类型 | 首屏重心 | 信息密度 |
| --- | --- | --- |
| 待办/审核 | 状态筛选、待处理队列、选中事项依据与处理操作 | 中高，列表可扫描，详情聚焦单对象 |
| 管理业务 | 范围摘要、对象列表、批次或流程状态 | 中高，允许适度批量入口 |
| 质量分析 | 事实指标、单一主图、明确下钻入口 | 中等，避免 BI 图表墙 |
| 领导只读 | 管理摘要、趋势、重点下钻 | 中等偏低，不提供处理按钮 |

### 2.5 响应与局部交互原则

- 宽屏审核页面可采用列表与详情双栏；窄屏时先保留筛选与列表，详情通过抽屉进入。
- 筛选条件在进入详情或返回列表后应保持，以支持连续处理。
- 对关键处理动作使用确认弹窗，明确依据、状态结果和处理记录。
- 无权限访问时展示权限说明和可返回入口，不展示真实业务数据。

## 三、页面模式

### 3.1 审核处理模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 公开线索审核页、部门成果初审页、部门评聘初审页、部门考核审核页、部门绩效审核页 |
| 首屏优先级 | 当前范围与待办摘要 > 筛选和处理队列 > 证据/材料详情 > 处理动作与记录 |
| 主操作 | 审核、转为候选、要求补充、退回、驳回或转交，按业务和授权确定 |
| 推荐结构 | 筛选摘要区 + 可扫描列表 + 详情处理区 + 审核历史 |
| 不可出现 | 系统任务重试、规则发布、服务日志、无人工依据的自动入档 |

### 3.2 业务管理模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 部门档案管理页、培训资源管理页、实践管理页、批次业务管理入口 |
| 首屏优先级 | 管理范围与业务阶段 > 待处理/异常摘要 > 对象列表 > 批次或分派动作 |
| 主操作 | 分派处理、查看待办、发起业务流程或导出清单，按权限提供 |
| 推荐结构 | 上下文与摘要 + 条件筛选 + 业务对象表 + 局部处理抽屉 |
| 不可出现 | 平台运行参数配置、底层接口状态或审计处置 |

### 3.3 质量分析模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 档案质量看板、部门培训看板、部门实践看板、校级画像分析页 |
| 首屏优先级 | 当前统计范围 > 少量事实型指标 > 一张主分析图 > 问题下钻列表 |
| 主操作 | 切换范围、查看部门/业务详情、导出事实清单 |
| 推荐结构 | 筛选栏 + 最多四项指标 + 单一主图 + 下钻表格 |
| 不可出现 | 未定义分母的完整率/覆盖率、无明确去向的图表堆叠、系统运行处置动作 |

### 3.4 汇总只读模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 校级领导管理摘要、授权只读的质量或趋势页面 |
| 首屏优先级 | 全局范围说明 > 管理摘要 > 趋势或结构发现 > 查看详情入口 |
| 主操作 | 查看下钻、切换范围、导出摘要 |
| 推荐结构 | 精简筛选 + 摘要卡 + 主图/重点列表 + 只读提示 |
| 不可出现 | 逐条审核、批量处置、配置和任务操作 |

## 四、组件语义与权限表达

### 4.1 核心组件

| 组件 | 用途 | 表达规则 |
| --- | --- | --- |
| 当前范围标识 | 确认列表与指标适用范围 | 在顶部上下文和筛选区可见，例如部门、业务条线或全校 |
| 事实摘要卡 | 快速看到待办和异常分布 | 数量须可解释和下钻；避免结论型评分 |
| 筛选工具条 | 快速聚焦处理队列 | 状态、组织、时间、对象类型优先，支持清除和保留上下文 |
| 轻表格/队列 | 浏览多对象并进入详情 | 关键状态、依据提示和最后处理时间可扫描 |
| 详情处理面板 | 对照依据完成业务动作 | 显示对象事实、来源材料、记录和授权动作 |
| 审核记录时间线 | 支撑责任追溯 | 显示业务处理人、动作、时间和意见，不替代系统审计日志 |
| 权限/只读提示 | 表达同页面在角色间的能力差异 | 明确为何不可操作，不伪造可点击按钮 |

### 4.2 状态与操作语言

| 场景 | 推荐状态或动作 | 禁止表达 |
| --- | --- | --- |
| 公开来源信息 | `待审核公开线索`、`转为候选`、`要求补充`、`驳回` | `自动入档`、`正式档案已生成` |
| 候选材料审核 | `待确认`、`确认入档`、`转异常` | 在无依据时一键通过 |
| 范围内异常 | `待处理`、`需补充依据`、`已转交` | 与系统任务失败混为一谈 |
| 主管分析 | `待补充材料数`、`待审核线索数`、`新增正式记录数` | 无口径的档案完整度、综合质量分 |
| 领导视图 | `查看详情`、`查看趋势` | `审核通过`、`批量处理` |

### 4.3 管理端与系统管理端边界

以下内容不得作为管理端的主操作或壳层入口：

- 同步、解析或通知任务的重试、暂停和运行日志定位。
- 规则版本的系统发布、回滚、停用和服务配置。
- 权限底层维护、系统健康诊断与审计导出。

业务主管部门涉及业务规则或数据导入的页面，如需与系统管理员共同访问，应按照已登记权限和具体页面方案定义业务动作，不能在通用管理壳层中默认加入系统运维能力。

## 五、首轮验证页面约束

### 5.1 `02-P-006` 公开线索审核页

| 项目 | 必须满足 |
| --- | --- |
| 页面模式 | 审核处理模式 |
| 授权角色 | 部门管理者、业务主管部门；页面应表达当前角色及数据范围差异 |
| 默认对象 | `ARCH-CLUE-2026-001`、`ARCH-CLUE-2026-002` |
| 首屏结构 | 组织/状态筛选、审核摘要、线索列表、来源与匹配详情、处理区域和审核记录 |
| 必须依据 | 来源网站、原文链接、发布时间、匹配教师、识别字段、匹配依据 |
| 主操作 | `转为候选`；并提供与授权匹配的 `要求补充`、`驳回` 或转交处理 |
| 状态结果 | 转为候选后等待后续人工确认入档，不能直接成为正式档案 |
| 禁止项 | 自动入档、档案完整度、系统规则发布、任务重试、系统日志处置 |

### 5.2 角色差异在验证页中的表达

| 角色 | 范围表现 | 动作表现 |
| --- | --- | --- |
| 部门管理者 | 显示当前部门范围，仅浏览本部门匹配线索 | 处理本部门线索、要求补充或按流程转交 |
| 业务主管部门 | 显示业务条线或授权跨部门范围 | 处理授权线索；是否提供批量/升级操作须由页面方案明确 |

## 六、禁止项

| 类别 | 禁止内容 |
| --- | --- |
| 角色混同 | 将管理端做成教师个人档案办理页面，或让校级领导默认承担逐条审核 |
| 系统越界 | 在管理端提供同步重试、配置发布、服务日志或系统审计处置 |
| 数据口径 | 公开线索直接入档；无计算标准的完整率、综合质量分或自动裁决 |
| 布局 | 将审核页面做成堆叠图表的大屏；将分析页面塞入大量单条处理操作 |
| 权限 | 不显示范围却展示跨组织数据；提供角色无权执行的可操作按钮 |

## 七、验收清单

### 7.1 规范级验收

- [ ] 页面是否持续表达当前角色与授权范围。
- [ ] 壳层是否继承 `tea-work` 海洋蓝顶部栏、白色分组业务导航、浅灰工作区和紧凑控件风格。
- [ ] 壳层是否包含业务导航、上下文栏、筛选/摘要和可扫描的主工作区。
- [ ] 审核处理、业务管理、质量分析、汇总只读四种模式是否边界清晰。
- [ ] 处理动作是否以证据和记录为支撑，且随角色权限变化。
- [ ] 是否明确排除配置发布、同步任务重试与系统日志处置。

### 7.2 成长档案验证页验收

- [ ] `02-P-006` 是否同时提供筛选、列表、来源匹配详情和审核记录。
- [ ] 部门管理者与业务主管部门的数据范围、动作差异是否可理解。
- [ ] 所有公开信息是否使用“待审核公开线索”或“待核实线索”语义。
- [ ] 处理结果是否为“转为候选”或要求补充，而不是直接入档。
- [ ] 页面是否避免系统端重试、发布、日志与教师端个人办理话术。
- [ ] 页面是否在视觉上保持管理业务端样式，而非误呈现为深色系统运维控制台。

## 八、后续使用规则

1. 具体管理页面方案必须继承本文的壳层、模式、权限表达和系统边界。
2. 同一页面支持多个管理角色时，页面方案必须逐一列明范围和动作差异。
3. HTML 原型仅在页面方案和新版 HTML 生成与验收规范确认后创建。

**方向确认记录（2026-05-25）**：使用者确认以本规范所定义的 `tea-work` 海洋蓝管理业务端风格作为后续管理端页面扩展基准。后续管理端页面须继承该壳层和视觉 Token，并根据各自业务模式配置内容区，不得改套系统管理端运维壳层。

**业务管理模式确认记录（2026-05-25）**：使用者确认 `02-P-004` 部门档案管理页 HTML 样板可作为管理端“业务管理模式”扩展基准。后续业务管理页面应继承其范围提示、事实摘要、待办列表和依据说明的组织原则；质量分析模式则须按本规范 `3.3` 另行验证，不直接复制待办列表布局。

**质量分析与领导只读模式确认记录（2026-05-25）**：使用者确认 `02-P-010` 档案质量看板 HTML 样板可作为管理端“质量分析模式 / 领导只读下钻模式”扩展基准。后续分析页面应沿用其事实指标、单一主图、口径说明和依据下钻方式；校级领导访问时保持只读，不展示办理入口。
