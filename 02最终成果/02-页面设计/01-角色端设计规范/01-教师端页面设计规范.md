## 一、端口定位与设计原则

### 1.1 端口定位

教师端是教师个人成长工作空间，围绕“我的事实、我的待办、我的补充、我的生成与结果”组织内容。它帮助教师查看已经形成的可信记录，发现需要自己完成的下一步，并在材料、申请、生成和更正流程中减少重复填报。

教师端不是业务管理后台、部门统计看板或系统运行控制台。页面不能让教师承担审核、配置、任务重试或跨人员管理职责。

### 1.2 设计原则

| 原则 | 设计要求 |
| --- | --- |
| 我的行动优先 | 首屏先回答“我现在需要处理什么”和“下一步在哪里完成”，主操作以个人可执行动作命名。 |
| 可信事实可追溯 | 正式数据应能查看来源、材料依据、入档/确认信息与引用情况。 |
| 辅助而非裁决 | AI 仅提示识别、建议或生成依据，保留本人确认、修改或提交动作。 |
| 提醒温和清晰 | 以待补充、待确认、需查看等可处理语义表达状态，不制造排名和压力。 |
| 内容分层明确 | 正式记录、待办事项、待核实信息和生成草稿不得视觉混放。 |
| 少填报可复用 | 优先展示系统已汇聚的事实和可复用内容，需要填写时说明为何需要补充。 |

### 1.3 业务表达边界

| 必须表达 | 不得表达 |
| --- | --- |
| 教师查看本人数据、上传材料、确认候选信息、查看结果、发起纠错 | 部门范围筛选、批量审核、规则发布、同步任务重试、审计处置 |
| “待核实线索”仍需管理人员核实，不能视为本人正式档案 | “自动入档”“AI 已判定”“档案完整度”或无标准综合分 |
| 正式档案条目与材料依据、数据来源、引用关系绑定展示 | 把线索、候选数据或 AI 建议直接混入正式记录 |

## 二、固定壳层与空间组织

### 2.1 壳层总结构

教师端采用轻量顶部导航和单页工作区，不使用后台式左侧多级管理导航。

```text
全局顶部导航：平台标识 / 我的业务入口 / 消息与帮助 / 教师身份入口
页面标题区：页面名称 / 个人上下文 / 简短说明 / 页面主操作
状态与行动区：与本人相关的待办、提醒或过程状态
内容工作区：本页主要对象、事实、表单、预览或结果
辅助提示区：来源说明、AI 依据、引用信息、帮助与下一步
抽屉 / 弹窗：事实详情、材料依据、纠错、导出确认等局部任务
```

### 2.2 区域职责

| 区域 | 固定职责 | 设计约束 |
| --- | --- | --- |
| 顶部导航 | 支持教师在个人业务、消息和个人设置之间切换 | 导航应扁平、可读，不暴露管理配置栏目 |
| 个人身份区 | 展示当前教师身份、所属组织及切换/退出入口 | 用于确认“这是我的空间”，不作为组织筛选器 |
| 页面标题区 | 明确本页任务与一项主要行动 | 主行动为上传、补充、提交、确认使用、导出等个人动作 |
| 状态与行动区 | 汇总影响当前页面的少量待办或提醒 | 不使用大规模指标墙，不展示排名或结论型评分 |
| 内容工作区 | 承载当前任务的核心内容 | 优先采用卡片、步骤、分区和清晰空状态，避免密集后台表格 |
| 辅助提示区 | 解释来源、材料、AI 依据或流程后续 | 弱于主要内容，但在需确认时可被直接访问 |

### 2.3 首屏层级

教师进入页面后的阅读次序应保持稳定：

1. 我正在查看什么，以及我能立刻做什么。
2. 是否有与我有关的待办、缺失材料或待确认事项。
3. 当前业务的正式事实、过程内容或生成结果。
4. 数据依据、使用说明、AI 辅助说明与后续跳转。

### 2.4 尺寸与响应原则

| 场景 | 约束 |
| --- | --- |
| 常规桌面 | 内容以单一主工作区为重心，可用辅助侧栏或抽屉查看依据。 |
| 较窄窗口 | 顶部导航保留核心入口；多列内容顺序堆叠，主行动不被折叠隐藏。 |
| 横向维度/步骤导航 | 优先保持完整顺序并允许横向滚动，不擅自改为管理筛选下拉框。 |
| 弹层 | 适合查看依据与确认操作，不新增未登记的主页面路由。 |

## 三、页面模式

### 3.1 个人总览模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 我的成长档案页、个人画像首页、我的培训首页、我的实践页、我的消息页 |
| 首屏优先级 | 本人标题与行动入口 > 待办提醒 > 正式事实或近期过程 > 辅助建议 |
| 主操作 | 上传材料、处理待确认、查看详情、进入任务 |
| 推荐结构 | 标题操作区 + 轻量提醒卡 + 业务维度/状态导航 + 个人事实卡片区 |
| 不可出现 | 部门人员列表、审核工作队列、系统任务健康或无依据综合评价 |

**成长档案样板应用**：`02-P-001` 使用该模式，展示 8 维导航、当前维度正式档案条目、个人待补充事项及独立待核实线索区域。

### 3.2 提交/补充模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 材料上传页、培训申请页、企业实践申请页、考核自评页、绩效自评页 |
| 首屏优先级 | 当前需要提交的内容 > 提交原因/缺失说明 > 填写或上传工作区 > 提交结果说明 |
| 主操作 | 提交材料、保存草稿、提交申请、补充说明 |
| 推荐结构 | 简短步骤提示 + 输入/上传主区 + 自动带入或识别结果 + 确认提交区 |
| 不可出现 | 将上传或 AI 识别结果表述为已审批、已认定或已正式入档 |

### 3.3 AI 辅助生成模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 智能填表页、教学档案生成页、写教学反思页、实践总结页 |
| 首屏优先级 | 生成目的和引用范围 > 已使用的数据依据 > 草稿或预览 > 本人确认使用 |
| 主操作 | 生成预览、修改草稿、确认并导出、查看来源 |
| 推荐结构 | 输入/类型选择 + 来源摘要 + 生成预览 + 人工确认区 |
| 不可出现 | AI 代替本人提交、自动更改正式档案或作出业务审批结论 |

### 3.4 个人结果查看模式

| 项目 | 规范 |
| --- | --- |
| 适用页面 | 成果认定详情页、评聘结果页、考核结果页、绩效结果页 |
| 首屏优先级 | 结果状态 > 结果依据与适用范围 > 过程记录 > 更正/异议或后续动作 |
| 主操作 | 查看依据、发起更正、提出异议、下载结果 |
| 推荐结构 | 结果摘要卡 + 依据分区 + 过程时间线 + 个人后续操作 |
| 不可出现 | 超越已公布结论的预测评分、他人排名或管理审批动作 |

## 四、组件语义与内容规则

### 4.1 教师端核心组件

| 组件 | 用途 | 表达规则 |
| --- | --- | --- |
| 页面主行动按钮 | 承载本人当前最重要的下一步 | 每页突出不超过一个；动词直接，例如“上传补充材料” |
| 待办提醒卡 | 告知需要本人处理的事项 | 显示对象、原因、截止/更新时间和行动入口 |
| 正式事实卡 | 展示可追溯、可复用的已确认记录 | 必须区分状态，提供来源与材料依据入口 |
| 待核实提示卡 | 展示可能相关但尚未核实的信息 | 使用“待核实线索”，与正式事实分区并说明尚待管理人员核实 |
| AI 辅助卡 | 展示识别、推荐或草稿来源 | 标明依据和需人工确认，不使用裁决语气 |
| 详情抽屉 | 展示事实、来源、材料、引用及版本 | 不改变主页面任务，不在抽屉内放置管理审核按钮 |
| 纠错/确认弹窗 | 完成本人明确确认的操作 | 说明影响对象、提交后流程或不反写正式档案的边界 |

### 4.2 状态表达

| 状态类型 | 推荐表达 | 不推荐表达 |
| --- | --- | --- |
| 已形成事实 | `已入档`、`已确认`、`已公布` | 含混的“已完成”而不说明对象 |
| 本人待处理 | `待补充`、`待确认`、`需提交` | 强警告式排名或扣分暗示 |
| 公共信息发现 | `待核实线索`、`待管理人员核实` | `疑似更新线索`、`自动采纳`、`待入档` |
| AI 输出 | `识别为候选信息`、`建议核对`、`基于以下依据生成` | `AI 判定通过`、`自动认定` |
| 空状态 | `当前维度暂无正式档案，可上传材料补充` | 用统计分数替代空状态说明 |

### 4.3 数据与指标约束

- 个人页面仅呈现与本人行动和可信事实直接相关的数量，例如待补充事项、待确认事项和待核实线索数量。
- 未定义计算标准时，不展示“档案完整度”、成长指数、综合得分、排名或预测结果。
- 成长档案的正式条目、候选数据和待核实线索必须保持分区与状态区分。
- 业务数据和示例对象应来自共享模拟数据与业务旅程基线，不为视觉填充临时创造跨页状态。

## 五、首轮验证页面约束

### 5.1 `02-P-001` 我的成长档案页

| 项目 | 必须满足 |
| --- | --- |
| 页面模式 | 个人总览模式 |
| 首要任务 | 查看正式档案事实，发现需要本人完成的补充动作，并理解待核实线索的边界 |
| 导航 | 使用固定顺序的 8 维导航；默认可承接 `D4 企业实践` 待补充事项 |
| 正式内容 | 正式档案条目使用事实卡，支持查看来源、材料依据和引用情况 |
| 非正式内容 | 待补充事项和待核实线索均与正式档案视觉分区 |
| 主操作 | `上传补充材料` |
| 禁止项 | 档案完整度、部门筛选、线索审核按钮、任务重试或系统日志 |

## 六、禁止项

| 类别 | 禁止内容 |
| --- | --- |
| 布局 | 后台式左侧多级管理导航；以大表格和指标墙作为个人首屏主体 |
| 角色越界 | 审核他人材料、批量处理、发布规则、执行系统重试、查看审计日志 |
| 业务口径 | 无标准综合指标；线索直接入档；候选信息冒充正式事实 |
| AI 表达 | AI 自动裁决、自动审批、自动修改正式档案 |
| 情绪语气 | 以排名、落后、强告警驱动教师处理常规事项 |

## 七、验收清单

### 7.1 规范级验收

- [ ] 页面首屏是否围绕本人事实与“我的下一步行动”组织。
- [ ] 是否采用顶部个人工作空间壳层，而非后台式左侧多级管理导航。
- [ ] 个人总览、提交/补充、AI 辅助生成、个人结果查看四类模式是否可以覆盖教师主要页面。
- [ ] 组件是否支持来源、材料依据、引用与本人确认的业务表达。
- [ ] 状态语气是否温和、明确且不引入无依据评价。

### 7.2 成长档案验证页验收

- [ ] `02-P-001` 是否完整展示 8 维导航。
- [ ] 正式档案条目、待补充事项与待核实线索是否被清晰分隔。
- [ ] 待核实线索是否只提示查看摘要并说明待管理人员核实。
- [ ] 是否避免“档案完整度”或类似无依据指标。
- [ ] 是否避免管理筛选器、审核主操作和系统运维操作。

## 八、后续使用规则

1. 具体教师页面方案必须继承本文的壳层、页面模式、组件语义与禁止项。
2. 业务模块契约只补充字段、状态和动作，不得覆盖本文规定的端口布局。
3. HTML 原型仅在对应页面方案和新版 HTML 生成与验收规范确认后创建。

**方向确认记录（2026-05-25）**：使用者确认以本规范所定义的教师个人成长工作空间方向作为后续教师端页面扩展基准。后续教师端页面须保持本人事实、本人待办与本人行动优先，不得改造成管理审核或系统运行工作区。
