# 教师综合发展平台页面范围与角色清单

> **版本**：V1.0
> **编制日期**：2026年5月22日
> **文档定位**：页面范围与授权角色台账，用于汇总各模块 PRD 中的角色、功能和页面范围；本文不定义教师端、管理端、系统管理端的布局和视觉方案。
> **使用状态**：保留精修。后续角色端设计规范和业务契约均以本文核对页面覆盖范围。
> **依据文档**：02-12 模块 PRD V1.2

---

## 一、文档定位

本文档用于把各模块 PRD 中分散的“角色、需求、功能、页面”统一汇总，形成平台级页面设计清单。

本文档不替代模块 PRD，也不替代单模块高保真页面设计说明文档。它主要回答三个问题：

- 不同角色进入平台后需要看到哪些页面？
- 每个模块需要设计哪些核心页面和二级页面？
- 哪些页面可以复用、合并或按不同角色视图处理？

> 系统级 HTML 原型生成说明：本文档用于核对角色和能力覆盖；页面 ID、规范文件名和生成进度以 `05-原型生成输入/16-全站页面路由与输出清单.md` 为准，跨页人物、状态和旅程以 `05-原型生成输入/17-共享模拟数据与业务旅程基线.md` 为准。

## 二、按角色汇总页面

### 2.7 平台模块间能力

以下对象不是独立用户角色，通常不需要单独页面，但需要在接口、引用、状态和页面跳转中体现。

| 模块关系 | 核心功能 | 页面设计要求 |
|----------|----------|--------------|
| 成长档案 → 其他模块 | 正式档案数据共享与引用 | 在业务页面展示数据来源、材料依据和引用状态 |
| 教师画像 → 培训/实践/教研/成果 | 发展建议跳转和反馈 | 在建议卡片中提供跳转入口和采纳状态 |
| 培训/反思/实践/教研 → 成长档案 | 结果沉淀 | 在完成页展示“已沉淀/待确认/异常”状态 |
| 成果认定 → 评价模块 | 正式认定结论引用 | 在评聘、考核、绩效页面展示认定结论和依据 |
| 消息中心 → 全模块 | 消息提醒和业务跳转 | 消息详情需能跳转到对应业务页面 |

### 2.8 平台公共能力页面

以下页面属于平台级基础能力，不归入单一业务模块，但需要作为高保真原型和前端页面规划的一部分统一设计。

| 能力类别 | 核心功能 | 主要页面 |
|----------|----------|----------|
| 入口认证 | 登录、统一身份认证、多角色进入 | 登录页、角色选择页 |
| 个人设置 | 个人信息、联系方式、安全信息、通知偏好 | 个人中心页、通知偏好页 |
| 全局检索 | 跨模块检索页面、记录、消息和材料 | 全局搜索页 |
| 权限组织 | 角色、组织范围、数据范围、授权有效期 | 权限配置页、组织与角色管理页 |
| 公共配置 | 流程、字段、指标、AI 治理策略 | 公共流程配置页、公共字段字典页、公共指标口径页、AI 治理策略页 |
| 审计留痕 | 操作日志、配置变更、权限变更、异常审计 | 操作日志与审计页 |

## 四、页面类型归类

## 五、页面命名与复用建议

### 5.1 命名规则

| 场景 | 命名建议 | 示例 |
|------|----------|------|
| 教师个人入口 | 使用“我的 + 业务对象” | 我的成长档案页、我的培训首页、我的绩效考核页 |
| 申请表单 | 使用“业务对象 + 申请页” | 培训申请页、企业实践申请页、评聘申请页 |
| 审核页面 | 使用“范围 + 业务对象 + 审核页” | 部门培训审核页、部门考核审核页 |
| 配置页面 | 使用“业务对象 + 配置页” | 培训配置页、评聘配置页、数据规则配置页 |
| 统计看板 | 使用“范围/对象 + 看板/分析页” | 档案质量看板、部门实践看板、校级画像分析页 |

### 5.2 可复用页面模式

| 可复用模式 | 适用页面 | 复用建议 |
|------------|----------|----------|
| 我的申请列表 | 我的成果申报页、我的评聘申请页、我的聘期考核页、我的绩效考核页 | 统一列表结构、状态标签、进度条和操作入口 |
| 审核处理页 | 部门成果初审页、部门评聘初审页、部门考核审核页、部门绩效审核页 | 统一材料区、意见区、操作区和历史记录 |
| 任务日志页 | 数据任务监控页、任务日志页、失败监控页 | 统一任务状态、失败原因、重试和日志详情 |
| 配置管理页 | 数据规则配置页、培训配置页、考核配置页、模板管理页 | 统一版本管理、启停状态、发布确认和审计 |

### 5.3 需要合并或统一入口的页面

| 页面组 | 建议 |
|--------|------|

| 校级画像分析页、校级反思分析页、校级教研分析页 | 可在高保真阶段统一看板布局和筛选组件 |
| 考核自评页、绩效自评页 | 表单结构高度相似，可复用自评表单模式 |

## 六、后续页面设计建议

- 先设计平台级导航和角色首页，再设计单模块页面。
- 先沉淀通用页面模式，再展开模块差异化页面。
- 教师侧优先保证“少填报、可确认、可生成、可追溯”。
- 管理侧优先保证“能筛选、能审核、能批量处理、能看进度”。
- 系统管理侧优先保证“配置有版本、任务可追踪、异常可重试、日志可审计”。
- 高保真原型阶段应优先覆盖教师、部门管理者、业务主管部门三个主角色。
