> **治理依据**：`README-页面设计文档使用说明.md`、`99-治理记录/19-页面设计文档冲突与修订清单.md`；恢复生成后改为引用新版 HTML 生成规范。

## 一、路由规则

### 1.1 页面类型与数量

| 类型 | 编号范围 | 数量 | 说明 |
|---|---:|---:|---|
| 首页与角色工作台 | `H-001` 至 `H-005` | 5 | 登录后的角色入口 |
| 成长档案 | `02-P-001` 至 `02-P-012` | 12 | 文档原编号 `P-xxx` 在 HTML 中统一补 `02-` |
| 教师画像至公共能力 | `03-P-001` 至 `13-P-012` | 106 | 按模块编号固定 |
| **合计** |  | **123** | 抽屉、弹窗、局部状态不计入主页面数 |

### 1.2 文件与导航要求

- HTML 文件固定使用 `{编号}-{页面名称}.html`，不得在批量生成中自造别名。
- `index.html` 是原型入口容器，不计入 123 个业务主页面。
- 页面内抽屉、弹窗和局部空/异常状态默认内嵌在所属页面中；只有独立演示需要时才增加非主路由文件。
- 所有主页面之间的关联跳转必须指向本文登记的 HTML 文件，并透传 `role`、`object` 和 `journey` 参数。

### 1.3 壳层代码

| 代码 | 壳层 | 适用角色 |
|---|---|---|
| `AUTH` | 登录前独立入口 | 全部用户、多角色用户 |
| `T` | 教师顶部导航 | 教师 |
| `M` | 管理业务左侧菜单 | 部门管理者、业务主管部门、校级领导、专家/评委 |
| `A` | 系统管理左侧菜单 | 系统管理员 |

URL、共享状态和动作路由中的 `role` 统一使用下表代码。专项办理角色不新增首页，其默认入口就是已登记的任务主页面。

| 角色代码 | 显示名称 | 默认入口 | 壳层 | 说明 |
|---|---|---|---|---|
| `teacher` | 教师 | `H-001` | `T` | 教师个人业务和成长路径 |
| `department_manager` | 部门管理者 | `H-002` | `M` | 学院审核、办理和分析 |
| `business_manager` | 业务主管部门 | `H-003` | `M` | 全校业务管理和规则发布 |

### 1.6 路由动作生成契约

本文负责固定“页面在哪里”，`05-原型生成输入/17-共享模拟数据与业务旅程基线.md` 第 10 节负责固定“用户从该页面做什么后到哪里”。生成原型路由时需同时遵循以下规则：

| 字段 | 生成要求 |
|---|---|
| `sourcePage` / `targetPage` | 必须使用本文登记 ID 和 HTML 文件名，不使用临时页面别名 |
| `trigger` | 由按钮、列表项、消息或菜单明确触发，主流程动作不可仅以 toast 表达 |
| `role` | 目标页按本文角色和壳层显示；跨角色办理从对应角色首页或消息进入 |
| `object` | 使用 `17` 登记的稳定业务对象 ID，不使用模块文档中的旧样例人物替代 |
| `journey` | 使用 J-00 至 J-06，跨页导航持续透传 |
| `stateMutation` | 提交、审核、发布、确认后按 `17` 更新状态和消息 |
| `permissionFallback` | 越权访问显示无权限状态，并提供回到授权入口的导航 |

头像菜单、全局搜索和退出登录等壳层级公共动作由 `J-00` 统一提供，不要求每个可承载该壳层的业务页面额外登记 `J-00`；页面旅程列仅登记该页面承担的业务或专项默认任务节点。
