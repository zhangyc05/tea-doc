## 一、生成边界

### 1.1 首批允许创建的页面

| 端口 | 页面 ID | 页面名称 | 固定文件名 | 角色 / 壳层 |
| --- | --- | --- | --- | --- |
| 教师端 | `02-P-001` | 我的成长档案页 | `02-P-001-我的成长档案页.html` | 教师 / `T` |
| 管理端 | `02-P-006` | 公开线索审核页 | `02-P-006-公开线索审核页.html` | 部门管理者、业务主管部门 / `M` |
| 系统管理端 | `02-P-009` | 数据任务监控页 | `02-P-009-数据任务监控页.html` | 系统管理员 / `A` |

页面输出路径固定为：

```text
docs/0新版设计/02最终成果/03-原型/02-成长档案模块/
├── 02-P-001-我的成长档案页.html
├── 02-P-002-待确认数据页.html
├── 02-P-004-部门档案管理页.html

├── 02-P-009-数据任务监控页.html
└── 02-P-010-档案质量看板.html
```

如当前获准页面确实共用样式、脚本或演示数据，可在以下路径新建最小必要的共享资源：

```text
docs/0新版设计/02最终成果/03-原型/_prototype/
```

共享资源只服务于已获准生成的页面，不得借此提前创建其余主页面、全站模板库或已删除旧原型的替代副本。

### 1.2 当前不得执行的事项

- 除已授权的 `02-P-001`、`02-P-002`、`02-P-004`、`02-P-006`、`02-P-009`、`02-P-010` 外，不创建其他 HTML 主页面，包括首页、材料上传页或异常处理页。
- 不恢复、检索或参照已删除的旧 HTML、旧页面布局稿、旧生成总控与旧共享脚本。
- 不以业务模块契约反推三端统一壳层，也不将三端生成成相同骨架的菜单换皮页面。
- 不因首批演示需要修改路由、角色权限、共享对象或业务状态真值；如发现实际冲突，应先回到文档修订与确认。

## 二、固定读取顺序与真值职责

### 2.1 单页生成前必须按序读取

每生成或修改一个首批验证页面，必须按以下顺序读取有效文档：

| 顺序 | 文档 | 决定内容 |
| ---: | --- | --- |

## 四、文件与共享资源实现规范

### 4.1 文件组织

| 项目 | 要求 |
| --- | --- |
| 页面文件 | 仅按 `16` 登记的文件名创建，不改名、不另造别名 |
| 字符编码 | 使用 UTF-8，确保中文内容可直接打开浏览 |
| 独立打开 | 每个页面可作为静态 HTML 直接打开并展示基线状态 |
| 共享样式 | 仅当当前获准页面确有复用需求时创建 `_prototype/` 共享 CSS；端口差异必须保留 |
| 共享脚本 | 仅用于参数解析、演示状态、本批次通用弹层/辅助函数；不得提前搭建未生成页面逻辑 |
| 共享数据 | 从 `17` 中摘取首批所需稳定对象；对象名称、ID 与初始状态不得变造 |

### 4.2 URL 参数

生成页面须读取并保留以下参数：

| 参数 | 用途 | 首批要求 |
| --- | --- | --- |
| `role` | 当前演示身份 | 与 `16` 权限匹配时渲染相应视图；不匹配时显示无权限状态 |
| `object` | 当前业务对象 | 优先聚焦已登记对象；未知对象回退到本页默认对象并给出说明 |
| `journey` | 当前演示旅程 | 用于选择基线或对应状态变体，并在可用跳转中继续透传 |
| `state` | 可选局部演示状态 | 可用于三页内部展示已完成、失败、重试中等局部视图；不得冒充 `17` 未登记的跨页写入 |

参数拼接与读取应使用浏览器标准 URL API，不以易错字符串拼接维护参数。

### 4.3 分批生成中的待建目标处理

已生成页面的方案与旅程仍可能引用尚未生成的登记页面，例如当前的 `02-P-003` 或 `02-P-007`。在这些目标文件尚未创建前：

| 情况 | 实现要求 |
| --- | --- |
| 目标页属于 `16` 已登记但不在本批次创建范围 | 保留目标页面 ID、名称与应透传的参数语义；入口展示为`后续页面待创建`状态或说明弹窗，不产生指向不存在文件的可点击坏链接 |
| 目标页已经在后续获准批次创建 | 将入口改为真实导航，目标文件名必须与 `16` 一致并透传 `role`、`object`、`journey` |
| 目标页未在 `16` 登记 | 不创建、不链接；先回到路由台账确认 |

不得为了让首批按钮可跳转而临时生成空白 HTML 占位主页面，也不得将页面内抽屉冒充登记主页面。

## 五、交互、演示状态与可访问性

### 5.1 抽屉与弹窗

| 要求 | 说明 |
| --- | --- |
| 局部信息局部呈现 | 档案详情、线索摘要、任务日志等采用抽屉或页面详情区，不新增主路由 |
| 打开与关闭明确 | 可通过显式关闭按钮、遮罩点击（非关键确认）和 `Esc` 关闭；关闭后焦点返回触发元素 |
| 确认操作可取消 | 转为候选、驳回、纠错、任务重试等操作需弹窗确认或填写原因 |
| 反馈可持续查看 | 状态变化需体现在标签、记录、详情或反馈区域，不以短暂提示作为唯一结果 |

### 5.2 状态保存与重置

| 状态类型 | 首批实现要求 |
| --- | --- |
| 本页局部展示状态 | 可在当前页面内存或 URL `state` 参数中演示，并可通过刷新后的参数恢复 |
| 既有旅程状态写入 | 仅按 `17` 已登记动作和对象表达；当前三页无法完整走通的跨页动作不伪造持久写入 |
| 首批重置 | 每页提供回到基线状态的清晰操作或 URL 默认状态；后续完整原型再统一到 `index.html` 重置能力 |
| 共享状态存储 | 若为三页联动确需使用浏览器本地存储，应使用命名明确的首批状态键，并提供清除方式 |

### 5.3 基础可访问性

- 页面使用语义化标题层级、导航、主要内容、按钮、表格和表单标签。
- 所有可操作控件可由键盘聚焦并具有可见焦点状态。
- 图标不可作为唯一文字表达；状态、操作和告警必须包含文本。
- 弹窗/抽屉提供可识别标题、关闭控件与键盘关闭方式。
- 状态颜色不能是唯一识别方式，状态标签同时显示文字。
- 在较窄窗口下，主行动、任务对象、处理动作和日志入口仍可访问。
