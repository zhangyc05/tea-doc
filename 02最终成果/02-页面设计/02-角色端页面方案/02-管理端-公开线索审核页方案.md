## 一、页面核心任务

本页帮助授权管理人员核查公共来源信息与教师之间的匹配依据，决定是否将线索转为候选数据、要求补充依据或予以驳回。

公开来源信息在本页仍是`待审核公开线索`。页面处理结果只能进入候选或驳回状态，不能直接把线索写入教师正式档案。

**首要主操作**：`转为候选`，对应 `J-05` 中的线索处理结果。

## 二、角色、范围与默认对象

### 2.1 授权角色差异

| 当前角色 | 演示身份 | 页面范围表达 | 可执行动作 |
| --- | --- | --- | --- |
| 部门管理者 | `U-M-001` 周明远，智能制造学院 / 院长 | `智能制造学院`范围，查看匹配到本部门教师的待审核线索 | 转为候选、要求补充、驳回、按流程转交 |
| 业务主管部门 | `U-B-001` 陈璐，教师发展中心 / 主管 | 显示被授权的业务条线或跨部门范围 | 处理授权范围线索；批量或升级处理仅在后续授权明确时出现 |

本首轮页面默认以部门管理者 `J-05` 场景验证处理链路，同时必须提供业务主管部门切换后的范围与权限说明状态。

### 2.2 默认线索对象

| 对象 | 匹配教师 | 来源说明 | 初始状态 | 可能关联 |
| --- | --- | --- | --- | --- |
| `ARCH-CLUE-2026-001` 教学能力比赛获奖公示线索 | 林知夏 | 学校官网公示 | `待审核` | `D6` 成果荣誉 |

### 2.3 业务结果边界

| 操作 | 当前页面反馈 | 后续状态 |
| --- | --- | --- |
| `转为候选` | 展示人工核实已完成、即将进入确认流程的反馈 | `ARCH-CLUE-* -> 已转候选`，进入 `02-P-002`，等待确认入档 |
| `要求补充` | 记录需要补充的依据或说明 | 线索不进入正式档案 |
| `驳回` | 要求填写驳回原因并保留处理记录 | 线索不进入正式档案 |
| `转交部门` | 按权限展示的流程动作 | 更新待处理责任，不表示审核通过 |


## 四、审核摘要、筛选与队列

### 4.1 审核摘要

摘要卡仅表达当前筛选范围中的处理状态，例如：

| 摘要项 | 意义 | 可执行行为 |
| --- | --- | --- |
| 待审核 | 尚待人工核查来源与匹配依据的线索 | 筛选待审核队列 |
| 已转候选 | 已核实并进入候选确认链路的线索 | 查看处理记录或跳转候选待确认 |
| 已驳回 | 依据不充分或不匹配的线索 | 查看驳回原因 |
| 待补充 | 需要补足来源或匹配依据的线索 | 查看补充要求 |

不得展示`档案完整度`、线索转化率或无已确认口径的质量评分。

### 4.2 筛选工具条

| 筛选项 | 默认值 / 设计要求 |
| --- | --- |
| 当前范围 | 部门管理者默认`智能制造学院`；业务主管部门展示授权范围 |
| 审核状态 | 默认`待审核` |
| 来源类型 | 全部来源，可筛选学校官网公示、行业协会公开名单等已有来源 |
| 发布时间 | 可按时间区间筛选 |
| 关键词 | 搜索线索标题或匹配教师 |

筛选状态在查看详情和执行处理后应保持，支持连续审核。

### 4.3 线索处理队列

| 列表信息 | `ARCH-CLUE-2026-001` 示例 | `ARCH-CLUE-2026-002` 示例 |
| --- | --- | --- |
| 线索标题 | 教学能力比赛获奖公示线索 | 行业兼职任职公示线索 |
| 匹配教师 | 林知夏 | 林知夏 |
| 来源 | 学校官网公示 | 行业协会公开名单 |
| 可能关联维度 | 成果荣誉 | 社会服务 |
| 审核状态 | 待审核 | 待审核 |
| 主要进入动作 | 查看并处理 | 查看并处理 |

列表以待审核状态为主要扫描对象；不可将线索显示为正式档案记录。

## 五、来源与匹配详情区

### 5.1 详情必要信息

选中线索后，右侧详情区必须出现：

| 信息组 | 内容要求 |
| --- | --- |
| 来源原文 | 来源网站、原文标题或摘要、原文链接、发布时间 |
| 匹配对象 | 匹配教师林知夏、所在学院、可能关联档案维度 |
| 识别字段 | 从公开信息中识别出的候选字段和原文位置/依据 |
| 匹配依据 | 为何与该教师相关的人工可核对说明 |
| 风险提示 | `核实通过后仅转为候选数据，仍需确认后才能进入正式档案` |
| 审核记录 | 既有动作、处理意见、操作人和时间；初始可显示暂无处理记录 |

### 5.2 处理操作区域

| 操作 | 使用场景 | 交互要求 |
| --- | --- | --- |
| `转为候选` | 来源和匹配依据足以进入后续候选流程 | 弹窗再次说明不会直接入档；确认后显示已转候选和进入 `02-P-002` 的入口 |
| `要求补充` | 来源或匹配说明不足 | 填写补充要求，记录处理轨迹 |
| `驳回` | 不匹配或依据不足且无补充必要 | 填写理由并确认，保留驳回记录 |
| `转交部门` | 业务主管部门需转由匹配部门处理，或按流程具备该动作 | 明确新责任范围，不改变线索业务结论 |

## 七、关键交互与状态结果

| 触发动作 | 展现方式 | 结果 |
| --- | --- | --- |
| 点击某条线索 | 双栏详情更新 | 展示来源、匹配依据、识别字段和审核记录 |
| 点击原文链接/材料依据 | 预览抽屉或明确外链入口 | 查看公开来源内容，不改变状态 |
| 点击`转为候选` | 确认弹窗 | 明示“不直接入档”；确认后线索状态为`已转候选`，可进入 `02-P-002` |
| 点击`要求补充` | 意见弹窗 | 保存补充要求，状态显示待补充 |
| 点击`驳回` | 原因弹窗 | 保存驳回理由并更新处理记录 |
| 切换管理角色演示状态 | 上下文与列表刷新 | 范围和可用操作按角色调整，业务对象状态保留 |

## 八、禁止表达与验收清单

### 8.1 页面不得出现

- 将公开线索描述为正式档案、自动入档或自动审核通过。
- `档案完整度`、未定义完整率、综合质量评分等指标。
- 同步任务重试、系统日志、服务健康、配置发布或回滚动作。
- 教师端的本人材料补充式主任务或成长建议语气。
- 未说明授权范围的跨组织数据和按钮。

### 8.2 页面验收

- [ ] 页面继承管理端壳层，当前角色和数据范围在首屏可见。
- [ ] 壳层符合本机 `tea-work` 管理业务端风格，不误用系统管理端深色运维导航。
- [ ] 首屏具备审核摘要、筛选、线索队列、详情、动作及处理记录。
- [ ] 两条默认线索与共享数据基线完全一致。
- [ ] `转为候选`明确衔接候选确认流程，未直接形成正式档案。
- [ ] 部门管理者与业务主管部门的范围和动作差异已表达。
- [ ] 页面未出现系统管理操作、教师个人办理话术或禁止指标。
