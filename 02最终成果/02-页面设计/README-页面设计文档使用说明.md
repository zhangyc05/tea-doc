## 一、组织原则

页面视觉和布局必须以端口为主线，业务模块只提供业务内容。

| 主线 | 负责内容 | 决定页面布局 |
| --- | --- | --- |
| 教师端设计 | 教师查看个人事实、处理待办、补充材料和获得辅助 | 是 |
| 管理端设计 | 部门/业务主管/校级管理角色筛选、审核、分析与下钻 | 是 |
| 系统管理端设计 | 系统管理员配置、任务监控、异常处理与审计 | 是 |
| 业务模块契约 | 对象、字段、状态、动作和跨角色规则 | 否 |
| 原型生成输入 | 页面编号、路由、演示数据和后续验收约束 | 否 |

授权角色可以多于端口数量。例如部门管理者和业务主管部门可以共用管理端布局，但数据范围与操作权限不同。

## 三、已删除内容

下列内容已从当前设计体系中删除，以免 AI 把过期布局或模板化页面当作依据：

| 类别 | 已删除内容 |
| --- | --- |
| 历史规则与记录 | 旧页面设计说明书、旧 UI 规则、系统级预演与修复记录 |
| 旧角色布局底稿 | 三端布局与导航总则底稿、旧页面设计总控、旧首页与工作台方案 |
| 待重建模块页面稿 | 教师画像、培训、反思、实践、教研、成果、评聘、考核、消息中心及公共能力旧稿 |
| 旧生成约束 | 旧 HTML 原型生成规范、旧系统级生成总控 |
| 旧页面实现 | `../03-原型/` 下的旧 HTML 页面、共享脚本、路由数据和测试 |

被删除文件不再作为抽取素材，也不应被恢复到 AI 读取清单中。后续模块业务契约应依据 PRD 与已确认数据基线重新编写。

## 四、当前 AI 阅读规则

### 4.1 文档整理与需求校对

| 顺序 | 读取内容 | 用途 |
| --- | --- | --- |
| 1 | 本 README | 确认有效范围和删除边界 |
| 2 | `99-治理记录/19-页面设计文档冲突与修订清单.md` | 确认重建原则 |
| 3 | `00-页面范围与角色清单.md` | 核对页面和角色范围 |
| 4 | `05-原型生成输入/16-全站页面路由与输出清单.md` | 核对页面 ID、权限与跳转 |
| 5 | `05-原型生成输入/17-共享模拟数据与业务旅程基线.md` | 核对示例数据和状态变化 |
| 6 | `03-业务模块契约/02-成长档案业务页面契约.md` | 处理成长档案页面时读取业务事实 |

### 4.2 未来生成页面

正式文档补齐后，单页 HTML 生成顺序应为：

| 顺序 | 文档类型 | 决定内容 |
| --- | --- | --- |
| 1 | 所属角色端设计规范 | 壳层、导航、组件模式与视觉密度 |
| 2 | 所属角色端页面方案 | 信息结构、首屏重心与关键操作 |
| 3 | 对应业务模块契约 | 业务字段、状态、动作与禁止表达 |
| 4 | 路由与共享数据基线 | ID、权限、跳转、示例数据与回写 |
| 5 | 后续新建的 HTML 生成规范 | 文件输出和验证方式 |

不得从业务模块契约反推教师端、管理端或系统管理端的整体布局。

## 五、恢复原型生成前的门槛

1. 新建教师端、管理端、系统管理端三份正式设计规范。
2. 新建三个验证页面方案：教师端我的成长档案、管理端公开线索审核或档案质量看板、系统管理端数据任务监控。
3. 新建 HTML 生成与验收规范，不引用已删除旧稿。
4. 校验 `16`、`17` 与新方案中的页面 ID、角色权限、示例状态一致。
5. 验证三种端口页面确实具有不同布局，而非同一模板替换菜单。

在这些门槛满足前，不创建或扩展 HTML 原型。
