# 页面设计文档冲突与修订清单

> **文档性质**：页面设计文档治理记录，不是 HTML 原型生成输入。  
> **编制日期**：2026-05-24  
> **当前结论**：页面设计改为按教师端、管理端、系统管理端组织；旧布局稿、模板化模块稿、旧生成稿和旧 HTML 原型已删除，避免继续影响后续设计。

---

## 一、为什么删除旧稿

此前页面设计文档按业务模块展开，并在模块内重复描述多个角色页面。这种组织方式会带来三个直接问题：

1. 教师端、管理端、系统管理端缺少各自稳定的布局主线，AI 容易生成同一种框架的换皮页面。
2. 模块旧稿混合了业务事实、视觉布局、生成约束和历史状态，局部修订仍会留下冲突信息。
3. 旧 HTML 生成文档建立在旧路由与旧布局理解上，在三端方案未重建前继续保留会制造误导。

因此，本轮采用“保留稳定契约，删除有歧义旧稿，按角色重新设计”的处理方式。

## 四、已经确认的设计口径

| 事项 | 确认口径 |
| --- | --- |
| 布局组织 | 页面按教师端、管理端、系统管理端设计，模块契约不决定全局布局 |
| 成长档案指标 | 不展示没有计算标准的“档案完整度”或类似结论型指标 |
| 公共渠道数据 | 使用“待核实线索”，表示需要人工核实后才能进入正式档案的信息 |
| 教师成长档案 | 展示 8 维导航与正式档案条目，待核实线索不得混入正式条目 |
| 管理端 | 聚焦筛选、审核、质量分析和下钻，不混入系统发布、重试、日志操作 |
| 系统管理端 | 聚焦配置、任务、失败处理和审计，不混入教师个人或业务审核话术 |
