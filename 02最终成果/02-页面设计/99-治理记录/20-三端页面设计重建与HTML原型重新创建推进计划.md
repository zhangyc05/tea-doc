# 三端页面设计重建与 HTML 原型重新创建推进计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先建立教师端、管理端、系统管理端三套稳定页面设计依据，再以成长档案三个新建代表页面验证布局方向，确认后逐步创建 HTML 原型。

**Architecture:** 页面设计以角色端规范和角色端页面方案为上位输入；业务模块契约只提供对象、字段、状态与动作；路由和共享数据文档负责行为一致性；HTML 生成规范最后建立。旧 HTML 原型目录已删除，首轮仅按新规范创建三个验证页面，不直接铺开全站页面。

**Tech Stack:** Markdown 设计契约、现有静态 HTML/CSS/JavaScript 原型、浏览器人工验收与路由/文案检索校验。

## 一、执行目标与边界

### 1.1 本轮需要解决的问题

| 问题 | 本轮处理方式 |
| --- | --- |
| 页面按模块编写，三类端口布局不稳定 | 新建三份角色端设计规范，端口布局由其唯一决定 |
| AI 容易沿用旧稿或生成同款换皮页面 | 旧稿已删除；计划只引用现存白名单文档与后续新文档 |
| 尚不确定新的 HTML 是否符合预期 | 先写方案，再只创建三个成长档案验证页 |
| 成长档案存在业务口径要求 | 继续使用已确认的待核实线索、8 维导航、正式档案条目等口径 |

### 1.2 不在首轮范围内的事项

- 不立即创建全部 123 个主页面。
- 不先建设覆盖所有模块的完整组件库或大型设计系统。
- 不直接修补旧模块页面说明文档；未保留模块以后根据 PRD 新建业务契约。
- 不恢复或参照已删除的旧 HTML 视觉表现。
- 不展示没有计算标准的“本人档案完整度”、综合指数或类似结论型指标。

### 1.3 首轮完成的判定

首轮在以下条件全部满足时结束，并提交是否扩展原型的决策：

- 三份角色端正式设计规范完成并经人工确认。
- 三份成长档案验证页面方案完成并经人工确认。
- 新版 HTML 生成与验收规范完成。
- 三个验证 HTML 页面按照新规范新建并完成验收。
- 三个页面明显体现教师端、管理端、系统管理端的布局差异。
