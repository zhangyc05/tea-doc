## 二、核心公共规则

### 2.1 统一流程引擎

```text
草稿 → 已提交 → 审核中 → 退回补正 / 审核通过 → 已完成 / 已归档
```

支持草稿保存、退回补正、多级审核、审批留痕、批次管理和归档。

流程类模块应明确区分不同业务对象，例如申请单、需求单、成果线索、认定记录、考核批次、个人考核记录、绩效应用依据等。状态流转不得混写，正式记录与临时补充材料必须有清晰边界。

### 2.2 数据分工

- 成长档案：保存事实记录。
- 成果认定：形成正式认定结论。
- 评价应用：成果类数据必须优先引用已认定成果，成果类补充材料不得绕过认定直接计分。

### 2.3 统一消息中心

所有推动业务流转的关键节点，统一通过消息中心触发和留痕；消息中心负责触达，不负责生成业务判断。

消息中心统一承接消息事件、模板、接收对象、站内消息、外部通道、已读状态、业务跳转、失败重试和发送统计。各业务模块负责提供消息来源、业务对象、接收范围和跳转目标。

### 2.4 统一权限模型

```text
权限 = 角色 × 组织范围 × 数据范围
```

### 2.5 AI治理

- 辅助不替代
- 人工确认
- 结果可解释
- 用户可修正
- 异常可降级

### 2.6 公共字段字典

统一字段建议包括：申请理由、预期目标、补充材料、审核意见、当前状态、退回原因、归档时间。

### 2.7 公共指标规范

所有指标至少包含：指标名称、计算口径、统计周期、数据来源、目标值。

## 三、模块复用要求

| 模块 | 必须复用能力 |
|------|-------------|
| 教师培训 | 流程引擎、消息中心、AI治理、公共字段 |
| 企业实践 | 流程引擎、消息中心、AI治理、公共字段 |
| 教学反思 | 消息中心、AI治理、公共指标 |
| 虚拟教研室 | 消息中心、公共状态与指标 |
| 成果认定 | 流程引擎、AI治理、消息中心 |
| 职称评聘 | 流程引擎、消息中心、成果认定结果引用 |
| 聘期考核 | 流程引擎、消息中心、成果认定结果引用 |
| 绩效考核 | 流程引擎、消息中心、成果认定结果引用 |
| 消息中心 | 权限模型、用户偏好、操作日志、公共指标 |

## 四、验收清单

| 检查项 | 验收要求 |
|--------|---------|
| 流程复用 | 适用模块未重复建设独立流程能力 |
| 消息复用 | 关键节点均由消息中心统一触发 |
| 权限复用 | 权限设计符合三维模型 |
| AI治理 | AI 模块具备确认、解释、修正、降级能力 |
| 数据边界 | 成长档案与成果认定职责清晰，评价应用无旁路 |
| 字段一致性 | 公共字段命名和含义统一 |
| 指标一致性 | 指标具备明确口径、周期和来源 |
| 对象边界 | 概念相近的对象已区分用途、状态和是否形成正式记录 |
| 消息闭环 | 消息具备事件来源、接收对象、触达记录、已读记录和异常补偿 |
| 审计留痕 | 关键配置、审核、更正、撤回、归档动作具备日志和版本记录 |
